階段工作項目驗收證據風險處置
Phase 1：版本盤點確認目前 toolchain、module go directive、CI image 與部署平台。go version、go env、CI 設定。舊版環境先隔離驗證。
Phase 2：功能導入只導入本頁列出的高價值功能，不做無關重構。對應測試與範例。每個功能以小 PR 驗證。
Phase 3：相容性清理處理移除、棄用、安全收緊與指令變更。CI 綠燈與風險清單。保留 rollback branch。
Phase 4：發布紀錄記錄 major release 與 patch revisions 採用依據。Release note、更新資料、測試輸出。不以口頭結論取代證據。

測試變 flakyruntime、time、scheduler、network 或 filesystem 行為被修正。重跑 -count=1、race test，並隔離外部依賴。
部署環境無法啟動OS、architecture、cgo、linker 或憑證環境差異。建立平台 matrix 與最小 smoke test。

建議原因落地方式
每次升級都保留官方來源避免文件與官方事實漂移。頁尾與索引保留 go.dev 連結。
Patch revisions 不獨立成頁major version 才是教學與升級主體。patch 摘要收斂到本頁表格。
以測試證據收斂風險release note 不是成功升級的證據。build、test、vet、smoke、benchmark 依版本風險選用。

Release Note 專欄 / Go 1.25

Go 1.25：容器感知 GOMAXPROCS 與可控併發測試

Go 1.25 對雲端服務很重要：runtime 開始理解 Linux container CPU limit，testing/synctest 讓併發與 timeout 測試不再依賴脆弱的 sleep。

Runtime

Container-aware GOMAXPROCS

  • Linux container 內預設 GOMAXPROCS 會考慮 cgroup CPU bandwidth limit。
  • runtime 也可週期性更新可用 CPU 或 cgroup limit 的變化。
  • 手動設定 GOMAXPROCS 或呼叫 runtime.GOMAXPROCS 會停用自動行為。
Testing

testing/synctest

  • 用隔離 bubble 與虛擬時間測 goroutine、timer、timeout。
  • 適合 context deadline、background worker、channel 協調測試。
  • 減少 time.Sleep 導致的慢測試與 flaky test。
Vet

waitgroup / hostport Analyzer

新的 vet analyzer 能抓出 sync.WaitGroup.Add 放錯位置，以及用字串拼接 host:port 造成 IPv6 不相容的問題。

專案影響

Kubernetes 服務調校

服務升到 Go 1.25 後，CPU limit、worker count、queue depth、latency SLO 要一起重測；不要沿用舊版固定 GOMAXPROCS 假設。

檢查項建議
Kubernetes CPU limit比對升級前後 runtime.GOMAXPROCS(0)、p95 latency、CPU throttling。
併發測試把 sleep-based timeout 測試逐步改為 testing/synctest。

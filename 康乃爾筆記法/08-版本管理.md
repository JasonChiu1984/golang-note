# 08. 版本管理 (Go Modules) — 康乃爾筆記

> **日期**：2026-05 ｜ **版本基準**：Go 1.26.3 ｜ **學習目標**：精通 go.mod、go.sum 及 Go Workspace 實務

---

| 🔑 線索欄（關鍵字 / 問題） | 📝 筆記欄（詳細內容） |
|:--|:--|
| **Go Modules 是什麼？** | Go 1.11 引入的官方依賴管理方案，取代舊的 `GOPATH` 模式。<br>核心檔案：`go.mod` (描述依賴) 和 `go.sum` (安全校驗碼) |
| **Semantic Versioning (SemVer)** | `vMAJOR.MINOR.PATCH` (例：`v1.2.3`)<br>MAJOR：破壞性更新<br>MINOR：向後相容的新功能<br>PATCH：向後相容的 bug fix |
| **`go.sum` 為什麼要 commit？** | 它記錄了特定版本的 hash。確保團隊每個人、CI 伺服器 build 出來的 code 是 100% 相同的（可重現構建）。 |
| **`go mod tidy` 的作用** | 開發中最常用的指令。整理 `go.mod` 和 `go.sum`：<br>1. 下載程式碼中 import 但還沒記錄的套件<br>2. 移除 `go.mod` 中有記錄但程式碼沒用到的套件 |
| **升級依賴的方法** | `go get -u pkg`：升級 minor/patch<br>`go get pkg@v1.2.3`：指定版本<br>`go get pkg@latest`：升級到最新版 |
| **Major 版本更新規則 (v2+)** | 為了允許多版本共存，v2 以上的套件必須在 module path 加上 suffix。<br>例如：`require github.com/go-redis/redis/v8` |
| **Private Module 設定** | 公司內網套件，避免 Go 去公共 Proxy 找：<br>`export GOPRIVATE=github.com/mycompany/*` |
| **`replace` directive** | 在 `go.mod` 內強制將某依賴替換為本地路徑或 fork 版本。<br>⚠️ **缺點**：如果推到 remote，別人 clone 下來會因為找不到你本地路徑而 build 失敗。 |
| **Go Workspace (`go work`)** | Go 1.18+ 解決多 module 同時開發的現代方案（取代 `replace`）。<br>在根目錄 `go work init ./app ./lib`<br>優點：`go.work` 放 `.gitignore` 不干擾遠端 `go.mod`。 |

---

## 🗒️ 摘要

> Go 的套件管理嚴格遵守 SemVer 規範。日常開發熟記 `go mod tidy`；處理公司內部私有套件記得設 `GOPRIVATE`；遇到 Monorepo 或跨 module 本地開發時，優先使用 `go work` 而不是容易製造雷的 `go.mod replace`。

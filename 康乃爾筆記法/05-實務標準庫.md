# 05. 實務標準庫 — 康乃爾筆記

> **日期**：2026-05 ｜ **版本基準**：Go 1.26.3 ｜ **學習目標**：後端服務必備的標準庫知識

---

| 🔑 線索欄（關鍵字 / 問題） | 📝 筆記欄（詳細內容） |
|:--|:--|
| **為何不能用 default HTTP client？** | `http.Get()` 使用 `http.DefaultClient`，**沒有 timeout**，遠端服務掛掉時永遠等待<br>✅ `client := &http.Client{Timeout: 3 * time.Second}` |
| **HTTP response body 最常見的 bug** | 忘記 `defer resp.Body.Close()` → goroutine / 連線 leak<br>不讀 body 也要 close，或用 `io.Discard` |
| **`http.ListenAndServe` 的問題** | 無法 Graceful Shutdown，沒有 Timeout 設定<br>✅ 改用 `&http.Server{ReadTimeout: 5s, WriteTimeout: 10s, ...}` |
| **ReadTimeout 和 WriteTimeout 的差異** | `ReadTimeout`：讀取完整請求的最大時間（防 Slowloris 攻擊）<br>`WriteTimeout`：寫入完整回應的最大時間（防 handler 無限跑） |
| **Go 1.22 新路由語法** | `mux.HandleFunc("GET /users/{id}", h)` — 原生支援 Method + 路徑參數<br>取參數：`id := r.PathValue("id")`，不需要第三方 router |
| **Middleware 的型別簽名** | `func(http.Handler) http.Handler`<br>三個必備：**Logger**（記錄請求）、**Recovery**（捕獲 panic）、**RequestID**（追蹤） |
| **Graceful Shutdown 的步驟** | 1. 背景啟動 `srv.ListenAndServe()`<br>2. `signal.Notify(quit, SIGTERM, SIGINT)` 等信號<br>3. 收到信號後 `srv.Shutdown(ctx 30s)` 等待進行中請求 |
| **`database/sql` 連線池必設哪些？** | `SetMaxOpenConns(25)` — 最大連線數<br>`SetMaxIdleConns(10)` — 閒置保留數<br>`SetConnMaxLifetime(5min)` — 避免 DB 強制斷線 |
| **多筆查詢的三個必要步驟** | 1. `defer rows.Close()` — 務必 close<br>2. `rows.Next()` + `rows.Scan()` — 逐行掃描<br>3. `rows.Err()` — **迴圈後必須檢查**，不然錯誤被吞 |
| **Transaction 的 defer 慣例** | `defer tx.Rollback()` 放在 BeginTx 之後<br>若 Commit 成功，Rollback 是 no-op（不會雙重操作）<br>若中途 return error，自動 Rollback |
| **SQL Injection 防範** | 永遠用佔位符：PostgreSQL 用 `$1`、MySQL 用 `?`<br>✗ `"WHERE id=" + userInput` — 危險！<br>✅ `QueryContext(ctx, "WHERE id=$1", userInput)` |
| **`log/slog` vs 舊的 `log`** | 舊 `log`：只有文字，難以機器解析<br>`slog`：結構化（key-value），可輸出 JSON → ELK / CloudWatch 直接解析 |
| **生產環境的 slog 設定** | `slog.SetDefault(slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: slog.LevelInfo})))` |
| **`slog.With` 的用途** | 建立帶有固定欄位的 logger：`logger.With("request_id", id, "user_id", uid)`<br>請求處理鏈中每條 log 都自動帶上追蹤欄位 |
| **`time.Format` reference time** | Go 的格式字串不是 `YYYY-MM-DD`，而是 `2006-01-02 15:04:05`（固定 reference time）<br>⚠️ 最常踩的 Go 陷阱之一！ |

---

## 🗒️ 摘要

> 現代 Go 後端服務的三大基礎：**HTTP Server**（完整 Timeout + Middleware + Graceful Shutdown）、**database/sql**（連線池 + Transaction defer Rollback + 佔位符防注入）、**log/slog**（JSON 結構化日誌 + context 整合）。缺任何一個都不算生產就緒。

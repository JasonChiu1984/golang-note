# 03. 資料結構與物件感 — 康乃爾筆記

> **日期**：2026-05 ｜ **版本基準**：Go 1.22 ｜ **學習目標**：掌握 slice、map、struct、組合模式

---

| 🔑 線索欄（關鍵字 / 問題） | 📝 筆記欄（詳細內容） |
|:--|:--|
| **slice 的三個欄位是什麼？** | `ptr`（指向底層 array）、`len`（使用長度）、`cap`（容量）<br>共 24 bytes。賦值只複製 header，不複製資料。 |
| **`append` 的危險在哪？** | 容量不足時會新建底層 array，原來的 slice 不受影響<br>⚠️ 不要假設 append 後與原 slice 共享底層 array |
| **預分配 slice 的時機** | 知道大概長度時：`make([]int, 0, expectedLen)`<br>避免多次 append 觸發 reallocation |
| **`slices` 套件 (Go 1.21)** | 提供泛型陣列操作，取代手寫迴圈<br>`slices.Contains()`, `slices.Sort()`, `slices.Clone()` |
| **map 的零值行為** | `var m map[string]int` 的零值是 `nil`，讀取不 panic，但**寫入會 panic**<br>務必用 `make(map[string]int)` 或 `map[string]int{}` 初始化 |
| **map 存在性檢查** | `v, ok := m["key"]` — ok 是 bool，true 表示 key 存在<br>不 ok 時 v 是該型別的零值，不是 nil |
| **`maps` 套件 (Go 1.21)** | 提供泛型 Map 操作<br>`maps.Clone()`, `maps.Equal()` |
| **`strings.Builder` 為何優於 `+`** | `+` 每次建立新 string（O(n²)）<br>`strings.Builder` 直接寫入 buffer，用 `sb.String()` 取結果 |
| **`len("中文")` 為什麼是 6？** | `len` 回傳 byte 數。中文 UTF-8 每字 3 bytes<br>取字元數：`len([]rune("中文"))` 或 `utf8.RuneCountInString` |
| **`strconv.Atoi` vs `fmt.Sscanf`** | `strconv.Atoi`：最快、最常用的 string→int 轉換<br>`fmt.Sscanf`：功能強但有 reflection，速度慢 |
| **`regexp.MustCompile` 放在哪？** | **套件層級 var**，不要在函式/request 中每次 Compile<br>`var emailRe = regexp.MustCompile(`...`)` |
| **struct 的 Constructor 慣例** | `func NewUser(name string) *User`<br>回傳指標（可以是 nil 代表失敗）、可做驗證 |
| **value receiver vs pointer receiver** | Value：不修改、小 struct（如 `Point`）<br>Pointer：修改欄位、大 struct、需要 nil 判斷<br>**同一型別應統一使用同一種** |
| **Method Set 規則** | `T` 值：只能呼叫 value receiver 方法<br>`*T` 指標：可呼叫所有方法（value + pointer receiver）<br>**這決定 interface 是否滿足** |
| **Go 的繼承替代方案** | Struct Embedding（組合）：`type Dog struct { Animal }` → 提升欄位和方法<br>**Go 是 has-a，不是 is-a**。Dog 不能賦值給 Animal 變數 |
| **Embedding 的三個陷阱** | 1. 嵌入的是指標（`*Logger`）必須初始化，否則 nil panic<br>2. 多個 embedded 有同名方法 → 編譯錯誤（ambiguous）<br>3. 外層可覆蓋被嵌入型別的方法 |
| **Memory Alignment 是什麼？** | CPU 要求資料對齊到特定位址，Go 會插入 padding<br>最佳化：**欄位由大到小宣告**，減少 padding 浪費<br>驗證：`unsafe.Sizeof(MyStruct{})` |

---

## 🗒️ 摘要

> Go 無 class、無 inheritance，改用 struct + method + interface + embedding 組合出物件感。掌握 slice 的三欄位結構、map 的 nil 陷阱、pointer/value receiver 規則，以及 struct embedding 是組合（has-a）而非繼承（is-a）。

# 10. 效能調優與記憶體 — 康乃爾筆記

> **日期**：2026-05 ｜ **版本基準**：Go 1.26.3 ｜ **學習目標**：理解 GC、Escape Analysis、pprof、runtime metrics 與 benchmark A/B

---

| 🔑 線索欄（關鍵字 / 問題） | 📝 筆記欄（詳細內容） |
|:--|:--|
| **Stack vs Heap** | **Stack (堆疊)**：函式生命週期結束自動釋放，極快，無 GC 壓力。<br>**Heap (堆積)**：全域、動態大小物件，需依賴 GC 回收，成本高。 |
| **Escape Analysis (逃逸分析)** | 編譯器決定變數該放 Stack 還是 Heap 的過程。<br>「逃逸」指變數離開了當前函式的生命週期，被迫分配到 Heap。 |
| **常見的觸發逃逸情境** | 1. 回傳區域變數的**指標** (`return &user`)<br>2. 變數賦值給全域變數或 `interface{}` (`fmt.Println` 必逃逸)<br>3. 切片大小在編譯期未知 (`make([]int, n)`) |
| **如何觀察逃逸分析？** | `go build -gcflags="-m" .` |
| **指標一定比較快嗎？** | ❌ 錯誤觀念。<br>傳遞小 struct（< 64 bytes）用 Value 傳遞 (Stack) 往往比指標 (Heap + GC 開銷) 更快。**大 struct 才用指標**。 |
| **Garbage Collection (GC) 特性** | Go 使用 Concurrent Mark and Sweep。<br>優點：**極低的停頓時間 (Pause time < 1ms)**，適合 Web Server。<br>缺點：吞吐量 (Throughput) 開銷大，不適合高密度計算。 |
| **Green Tea GC (Go 1.26+)** | Go 1.26 起預設啟用，改善小物件標記與掃描 locality / CPU scalability。<br>不要只背「新版更快」：要用 `pprof`、`runtime/metrics`、真實 allocation profile 驗證工作負載。 |
| **`GOGC` 環境變數** | 預設 `GOGC=100`（Heap 成長 100% 時觸發 GC）。<br>調高（如 200）：減少 GC 次數，但吃更多 RAM。<br>調低：省 RAM，但耗 CPU。 |
| **GOMEMLIMIT (Go 1.19+)** | 軟性記憶體上限：`GOMEMLIMIT=500MiB`。<br>在 Container 環境中極度重要，避免 OOM Killed。 |
| **Memory Alignment (記憶體對齊)** | struct 欄位順序會影響佔用大小。<br>規則：**將欄位依型別大小（8B → 4B → 1B）由大到小排序**，可最大化減少 Padding 浪費。 |
| **`pprof` 是什麼？** | Go 內建的效能剖析工具。<br>引入 `_ "net/http/pprof"` 後，可透過 `/debug/pprof/` 取得 CPU、Memory、Goroutine 的即時 profile。 |
| **CPU / heap / goroutine profile 怎麼選？** | CPU 高 → `profile?seconds=30`；記憶體高 → `heap` / `allocs`；goroutine 變多或卡住 → `goroutine`。不要用同一種 profile 解所有問題。 |
| **block / mutex profile** | block profile 找 channel、timer、cond 等同步等待；mutex profile 找 lock contention。<br>兩者預設不完整啟用，診斷時用 `runtime.SetBlockProfileRate` / `runtime.SetMutexProfileFraction`。 |
| **Execution trace** | `go test -trace=trace.out` + `go tool trace trace.out`。<br>適合看 scheduler、syscall、GC、goroutine 時間線與平行度；不適合取代 CPU hot spot profile。 |
| **`runtime/metrics`** | 用穩定 key 讀 runtime 指標，例如 `/gc/heap/live:bytes`、`/gc/heap/goal:bytes`、`/sched/goroutines:goroutines`。<br>適合做長期監控與升級前後比較。 |
| **`benchstat`** | 正式效能比較應跑 `go test -run='^$' -bench=. -benchmem -count=10`，再用 `benchstat old.txt new.txt` 看統計差異。 |
| **Production profiling 原則** | 可在 production profile，但要限制入口、短時間取樣、一次收一種 profile，並記錄 profile 檔案與 commit SHA。 |
| **`sync.Pool` 的用途** | **重用**高頻分配的物件（如 `[]byte` buffer），極大降低 GC 壓力。<br>特性：放進去的東西隨時可能被 GC 清掉，不能當作資料庫連線池。 |

---

## 🗒️ 摘要

> Go 效能調優的核心在於「先定位症狀，再選工具，最後用 A/B 證據驗證」。Go 1.26 Green Tea GC 改善部分工作負載，但仍要用 benchmark、pprof、runtime metrics 與 trace 證明結論。

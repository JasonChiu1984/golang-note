# 04. 函式、錯誤、介面、泛型 — 康乃爾筆記

> **日期**：2026-05 ｜ **版本基準**：Go 1.22 ｜ **學習目標**：掌握 Go 的抽象模型

---

| 🔑 線索欄（關鍵字 / 問題） | 📝 筆記欄（詳細內容） |
|:--|:--|
| **具名回傳值的用途** | 1. 搭配 `defer` 做統一 error wrapping<br>2. bare `return`（短函式可讀性）<br>⚠️ 長函式不建議：難以追蹤當前值 |
| **閉包捕獲的是什麼？** | 捕獲外部變數的**參考**（reference），不是值的副本<br>⚠️ Go 1.21 以前的 `for` loop 陷阱：所有 goroutine 共享同一個 `i`<br>✅ Go 1.22 已修正：每次迭代建立新變數 |
| **`defer` 的參數估值時機** | 參數在 **宣告 defer 時**立即估值，不是執行時<br>`defer fmt.Println(x)` — x 已固定，即使後來 x 改變也無影響 |
| **函式作為一等公民** | 可存入變數、作為參數傳入（callback）、作為回傳值（decorator）<br>`type Handler func(ctx context.Context, input string) (string, error)` |
| **error wrapping 的規則** | 跨層傳遞時必須包裝：`fmt.Errorf("service.GetUser: %w", err)`<br>讓上層知道「在哪個情境發生」 |
| **`errors.Is` vs `errors.As`** | `errors.Is(err, target)`：判斷錯誤鏈中是否有特定**值**（如 `sql.ErrNoRows`）<br>`errors.As(err, &target)`：從錯誤鏈中取出特定**型別** |
| **nil interface 的陷阱** | `(*T)(nil)` 存入 interface ≠ `nil` interface（因為 interface 含 type info）<br>✅ 回傳 `nil` 而非 typed nil：`return nil, err` |
| **Interface 在哪裡定義？** | **在使用端（消費者）定義**，而不是實作端<br>讓使用端決定需要什麼行為 → 依賴反轉 |
| **小 interface 的好處** | `io.Reader`（1 method）比 `DatabaseClient`（20 methods）更容易 mock<br>建議：1-3 個 method 是最佳 interface 大小 |
| **編譯期 interface 檢查** | `var _ io.Writer = (*MyWriter)(nil)` — 不建立實例，只做型別檢查<br>放在 struct 定義旁邊，文件化意圖 |
| **泛型的適用場景** | 「型別不同，但演算法相同」：容器（`Stack[T]`）、工具函式（`Map[T,U]`）<br>⚠️ 不要用泛型取代 interface：行為抽象用 interface，容器/演算法用泛型 |
| **`~T` 約束的意義** | `~int` = 底層型別是 int 的所有型別（包含 `type UserID int`）<br>讓自訂型別也滿足約束 |
| **`comparable` 約束** | 允許使用 `==` / `!=`，可作為 map key<br>注意：`interface{}` 不是 comparable（可能 panic） |
| **何時從具體型別抽出 interface？** | 有第二個實作時（如加 mock 測試）<br>需要依賴注入時<br>⚠️ 不要過度抽象：先寫具體，有需要再抽 |

---

## 🗒️ 摘要

> Go 的抽象三件套：`error`（顯式處理）、`interface`（使用端定義小介面）、`generics`（演算法重用）。記住：nil interface 陷阱、閉包捕獲 reference、defer 參數立即估值，是最常出現在面試和生產 bug 的三個考點。

# 01. 環境與專案結構 — 康乃爾筆記

> **日期**：2026-05 ｜ **版本基準**：Go 1.22 ｜ **學習目標**：建立正確的 Go 專案基礎

---

| 🔑 線索欄（關鍵字 / 問題） | 📝 筆記欄（詳細內容） |
|:--|:--|
| **Q: Go 支援哪些平台？** | Linux (amd64/arm64/arm)、macOS (arm64/amd64)、Windows (amd64)、FreeBSD。<br>透過 `GOOS` / `GOARCH` 環境變數控制交叉編譯目標。 |
| **如何安裝 Go？** | macOS: `brew install go`<br>Linux: `apt install golang-go` 或官網 tarball<br>Windows: 官網 .msi 安裝程式 |
| **`GOPATH` vs `GOROOT`** | `GOROOT`：Go 工具鏈安裝位置（不要修改）<br>`GOPATH`：預設 `~/go`，放置 module cache 與 `go install` 的執行檔 |
| **`GOPROXY` 用途** | 控制下載 module 的來源。台灣常用：`GOPROXY=https://goproxy.io,direct`<br>企業內網：設定私有 proxy server |
| **`GOPRIVATE` 用途** | 跳過 proxy 和 sum check 的 pattern，如 `GOPRIVATE=github.com/mycompany/*` |
| **`go mod init` 做什麼？** | 在目錄下建立 `go.mod`，宣告 module 路徑與 Go 版本。是所有 Go 專案的起點。 |
| **`go mod tidy` 做什麼？** | 掃描程式碼，補齊缺少的依賴、移除多餘的依賴，確保 `go.mod` 和 `go.sum` 正確。 |
| **`package` 和 `module` 的差異** | Module：一個 `go.mod` 定義的單元，可含多個 package<br>Package：同一目錄下的 `.go` 檔案集合，import 時使用 |
| **`package main` 的特殊性** | 包含 `main()` 函式的 package，是可執行程式的進入點 |
| **大型專案目錄慣例** | `cmd/`：每個 binary 一個子目錄（保持極薄）<br>`internal/`：只有本 module 可 import 的邏輯<br>`pkg/`：可對外公開的工具（慎用）<br>`api/`：OpenAPI/proto 規格<br>`configs/`：設定範本<br>`deployments/`：Dockerfile、K8s manifests |
| **`go run .` vs `go build`** | `go run .`：編譯並立即執行，不留下執行檔（開發用）<br>`go build -o bin/app .`：產出執行檔 |
| **`go vet` vs `go fmt`** | `go fmt`：格式化程式碼（強制統一風格）<br>`go vet`：靜態分析常見錯誤（如 Printf 格式不符） |
| **`internal/` 的強制性** | Go **編譯器強制執行**：`internal/` 下的 package 只能被其父目錄及子目錄的 package import |

---

## 🗒️ 摘要

> Go 專案從 `go mod init` 開始，`go.mod` 是靈魂。善用 `cmd/`、`internal/` 目錄結構分離關注點，`GOPROXY` / `GOPRIVATE` 控制依賴下載來源，`go mod tidy` 保持依賴乾淨。

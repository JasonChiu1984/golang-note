# 09. 執行檔打包與部署 — 康乃爾筆記

> **日期**：2026-05 ｜ **版本基準**：Go 1.26.3 ｜ **學習目標**：掌握編譯優化、Docker 打包與 CI/CD 實務

---

| 🔑 線索欄（關鍵字 / 問題） | 📝 筆記欄（詳細內容） |
|:--|:--|
| **Go 編譯器的最大優勢** | 靜態編譯 (Statically linked)。編譯出的 binary 不依賴目標機器的 libc、Python/Node runtime 等環境，可以直接在空白系統（如 `scratch` docker image）運行。 |
| **如何交叉編譯？** | 設定環境變數即可：<br>`GOOS=linux GOARCH=amd64 go build -o app .` |
| **CGO 的影響** | `CGO_ENABLED=1`：允許 Go 呼叫 C 程式碼（如 sqlite3）。會導致 binary 變成動態連結，失去跨平台便利性。<br>✅ 生產環境**強烈建議 `CGO_ENABLED=0`**，確保 100% 靜態編譯。 |
| **減少 Binary 體積的方法** | `go build -ldflags="-s -w" .`<br>`-s`：移除符號表 (symbol table)<br>`-w`：移除 DWARF 除錯資訊<br>注意：這樣會導致 panic 時的 stack trace 沒有檔名和行號，需權衡。 |
| **編譯時注入版本號** | 透過 `ldflags -X`：<br>`go build -ldflags="-X main.Version=v1.0.0" .`<br>程式內的 `var Version string` 就會被替換為 "v1.0.0"。 |
| **Multi-stage Dockerfile 策略** | 階段 1：使用胖映像檔（如 `golang:1.22-alpine`）下載依賴、編譯 code。<br>階段 2：使用極瘦映像檔（如 `scratch` 或 `alpine`），**只**把編譯好的 binary 複製過來。<br>結果：Image size 從 800MB 縮減到 20MB。 |
| **Dockerfile 依賴快取優化** | 先 `COPY go.mod go.sum` 並 `RUN go mod download`，**然後**才 `COPY . .`。<br>只要 `go.mod` 沒變，Docker 就會快取下載好的依賴，大幅加速 build。 |
| **CI/CD 常見 Pipeline 步驟** | 1. **Lint**: `golangci-lint run`<br>2. **Test**: `go test -race -cover ./...`<br>3. **Build**: `GOOS=linux go build ...`<br>4. **Image**: `docker build ...`<br>5. **Deploy**: Push to Registry / Update K8s |
| **為何 CI 必須跑 `-race`？** | Race detector 會在執行時偵測是否有同時讀寫同一記憶體的狀況。<br>開發機很難測出併發 bug，CI 跑 test 加 `-race` 是最後防線。 |

---

## 🗒️ 摘要

> Go 的部署極度優雅：`CGO_ENABLED=0` 加上 Multi-stage Docker build，可以產出極小且零環境依賴的 Container Image。CI 階段務必加入 `golangci-lint` 與 `go test -race`，確保程式碼品質與併發安全。

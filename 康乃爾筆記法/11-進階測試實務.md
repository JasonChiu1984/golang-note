# 11. 進階測試實務 — 康乃爾筆記

> **日期**：2026-05 ｜ **版本基準**：Go 1.26.3 ｜ **學習目標**：掌握 Mock、Fuzzing 與外部資源整合測試

---

| 🔑 線索欄（關鍵字 / 問題） | 📝 筆記欄（詳細內容） |
|:--|:--|
| **Table-Driven Test 的精神** | 將「測試邏輯」與「測試資料」分離。<br>用 `[]struct{ name, input, want }` 迴圈跑 `t.Run()`。<br>好處：極易擴充 edge cases。 |
| **Test Coverage 指令** | `go test -coverprofile=c.out ./...`<br>`go tool cover -html=c.out` (開啟瀏覽器看哪行沒測到) |
| **手動 Mock vs Mock 框架** | Go 偏好**手動 Mock**，少用魔法框架（如 testify/mock）。<br>只要 Interface 定義夠小（1-2 methods），直接寫一個 MockStruct 實作它即可。 |
| **`t.Cleanup()` 的優勢** | 測試專用的 `defer`。無論測試成功、失敗或 Panic，都會保證執行。<br>✅ 取代 `defer` 來清理測試資源（如刪除假檔案、關 DB），避免 `t.Fatal` 時 defer 不執行的坑。 |
| **Fuzz Testing (模糊測試)** | Go 1.18+ 內建。系統自動產生大量隨機畸形字串、極端數字塞給你的函式，尋找 Panic 或無窮迴圈。<br>語法：`func FuzzParse(f *testing.F) { f.Fuzz(func(t *testing.T, data string) { ... }) }` |
| **`testing/synctest` (Go 1.25+)** | 用隔離 bubble 與虛擬時間測 goroutine、timeout、timer，不再靠 `time.Sleep` 猜等待時間。適合測 context timeout、背景任務停止與 channel 協調。 |
| **`T.ArtifactDir` (Go 1.26+)** | 測試可把 golden diff、截圖、profile、fuzz repro 寫到固定 artifact 目錄，讓 CI 收集產物比手動 `t.TempDir()` 更一致。 |
| **Request Decoding Contract** | 對 API service 來說，malformed JSON、unknown field、trailing JSON value 與空白必填欄位都應固定為 `400 invalid_input`，避免 decoder 錯誤漂成 `500`。 |
| **Readiness Contract Test** | 對 API service 來說，`/readyz=200/503` 是部署合約。測試要固定 ready 時回 200、draining 時回 503，避免 shutdown 期間仍被導流。 |
| **Queue Shutdown Test** | 對 worker queue 來說，close 後 enqueue 應回穩定錯誤，concurrent enqueue + shutdown 不應 panic。這類測試保護的是 goroutine 與 channel 的生命週期邊界。 |
| **Integration Test (整合測試)** | 會連線真實 DB 或 Redis 的測試。<br>常搭配 Go `build tags`（如 `//go:build integration`），讓一般 `go test` 跳過，只在 CI 特別執行。 |
| **Testcontainers** | 業界標準的整合測試方案。在測試檔內利用 Go 程式碼動態啟動 Docker Container（如 PostgreSQL），跑完測試自動刪除 Container。<br>確保測試環境 100% 乾淨且獨立。 |
| **`t.Helper()`** | 寫自訂測試輔助函式（如 `assertEq(t, a, b)`）時，第一行要加 `t.Helper()`。<br>作用：報錯時會印出「呼叫 assert 的那行」，而不是 assert 內部的行數。 |

---

## 🗒️ 摘要

> 現代 Go 測試金字塔：底層用 Table-Driven Test 與 Fuzzing 抓邊界；併發測試用 `testing/synctest` 與 shutdown race 測試降低 flaky；需要留下證據時用 artifact 目錄；API request decoder、錯誤格式與部署邊界用 contract test 固定；高層再用 Testcontainers 做真實整合測試。

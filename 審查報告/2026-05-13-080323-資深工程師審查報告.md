## 主要缺失

`production-api-worker` 已有 `/livez`、`/readyz` 與 `http.Server.Shutdown`，但 `/readyz` 永遠回 200。這會讓教材在 production lifecycle 上少一個關鍵觀念：process 活著不等於可接新流量。服務進入 shutdown 時應先轉為 draining，讓 load balancer 或 orchestrator 停止導流，再等待既有 HTTP request 與 queue job 收斂。

同時，原本 worker queue 用 signal context 啟動。當收到中斷訊號時，worker context 會被取消，可能比 queue drain 更早讓 worker 停止，無法清楚示範「已接受工作要先處理完」的 production shutdown 原則。

## 建議更新

1. 新增 lifecycle readiness 狀態，讓 service 可以在 ready / draining 之間切換。
2. 修改 `/readyz`，ready 時回 200，draining 時回 `503 Service Unavailable`。
3. 調整 `cmd/api-worker` shutdown flow：收到 signal 後先標記 draining，再 shutdown HTTP server，最後用 deadline 等待 queue drain。
4. 新增 readiness contract test，將 `/readyz` 的 ready / draining status code 視為外部操作合約。
5. 同步更新 README、第 7 章、第 11 章、進階速查、康乃爾筆記與 `production-api-worker` 文件，讓學生理解 liveness、readiness、draining 與 queue drain 的差異。

## 結論

本教程的專案深度與廣度已足以支撐「從 Go 語法到 production service」的學習路線。本輪建議不擴張新章節，而是補強 production service lifecycle，使既有 `production-api-worker` 更接近實務服務骨架。

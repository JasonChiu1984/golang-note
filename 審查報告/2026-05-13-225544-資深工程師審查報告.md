## 主要缺失

| 優先級 | 缺失 | 具體證據 | 風險 |
|---|---|---|---|
| P1 | `/jobs` 與 `/metrics` 缺少可測認證邊界 | `production-api-worker/internal/api/handler.go` 直接註冊 endpoint，沒有 auth middleware | 業務 endpoint 與 metrics 可能在部署環境被公開 |
| P1 | 安全標頭未形成統一 middleware contract | handler 只在 JSON response 設定 `Content-Type` | 不同 endpoint security header 行為不一致 |
| P2 | `compose-smoke.sh` 未支援認證情境 | smoke script 只送 `X-Request-ID` | 啟用 auth 後端到端 smoke gate 會失效 |
| P2 | 教材沒有明確區分 public probe 與 protected endpoint | README 與第 7 章主要聚焦 API contract / observability | 讀者可能把 `/readyz`、`/metrics`、business API 的安全邊界混在一起 |

## 建議修正

| 項目 | 修正方式 | 驗證 |
|---|---|---|
| API key security contract | 新增可選 `API_KEY`，啟用後要求 `Authorization: Bearer <token>` | `TestAPIKeyAuthContract` |
| Public health probe | `/livez`、`/readyz` 不套 auth，供 LB / orchestrator 探測 | `TestAPIKeyAuthContract` |
| Metrics protection | `GET /metrics` 在 `API_KEY` 有值時需認證 | `TestAPIKeyAuthContract` |
| Security headers | 所有 response 由 middleware 設定 `nosniff`、`DENY`、`no-referrer` | `TestSecurityHeadersContract` |
| Smoke script | `compose-smoke.sh` 讀取 `API_KEY` 並帶 Bearer token | `bash -n` 與後續 Compose smoke |
| 教材更新 | README、第 7 / 11 章、Cheat Sheet、API contract 文件同步補上 security gate | `rg` keyword check |

## 風險備註

`API_KEY` 是教學用最小 security gate，不等同正式 IAM。真實 production 仍應依部署拓撲評估 OAuth2、mTLS、API Gateway、WAF、rate limit、secret rotation、audit log 與網路隔離。本輪修正目標是把安全邊界納入可測教材，而不是一次完成企業級身分治理。

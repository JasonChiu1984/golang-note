## 1. Overview

v1.0.32 已將 pprof diagnostics contract 補成可測安全邊界，包含預設關閉、Bearer token、Go contract tests、runbook 與 CI gate。以專案開發深度來看，教材已經超過一般 Go 語法教程，具備 API contract、security、migration、DB pool、Prometheus、OpenAPI、pprof 與 Docker Compose smoke 的 production-oriented 教學骨架。

本輪仍可補強的最高價值缺口是 OpenTelemetry collector contract。教材與 `production-api-worker` 已有 trace exporter、Compose collector 與 runbook 描述，但 `production-api-worker/otel-collector.yaml` 尚未像 Prometheus / OpenAPI / pprof 一樣被獨立腳本與 CI 固定；同時本地 collector exporter 仍使用 `logging` 命名，對新版 collector 教學不夠穩定。

## 2. Architecture

| 層級 | 現況 | 風險 | 建議 |
|---|---|---|---|
| Go instrumentation | `internal/observability` 支援 stdout / OTLP exporter | 程式碼可產生 span，但 deployment pipeline 未被文件化檢查 | 保留現有設計 |
| Collector config | `otel-collector.yaml` 有 OTLP receiver 與 logging exporter | exporter / pipeline 名稱漂移時 CI 不會發現 | 改為 `debug exporter` 並新增檢查腳本 |
| Docker Compose | API 設定 `OTEL_EXPORTER_OTLP_ENDPOINT=otel-collector:4317` | Compose endpoint 可能與 collector receiver 不一致 | 納入 contract check |
| Runbook / README | 有 trace 說明，但沒有 collector gate | 值班流程知道 trace，但不保證 collector 可啟動 | 補上 OTLP collector contract |
| CI | 已檢查 Prometheus / OpenAPI / pprof | trace pipeline 不在 release gate 中 | 新增 `node scripts/check-otel-collector-contract.mjs` |

## 3. Configuration

建議固定下列本地教學 contract：

| 項目 | 固定值 |
|---|---|
| Collector 檔案 | `production-api-worker/otel-collector.yaml` |
| Receiver | OTLP gRPC `0.0.0.0:4317` |
| Exporter | `debug`，`verbosity: basic` |
| Trace pipeline | `receivers: [otlp]`、`exporters: [debug]` |
| API endpoint | `OTEL_EXPORTER_OTLP_ENDPOINT=otel-collector:4317` |
| Host port | `4317:4317` |
| 驗證入口 | `node scripts/check-otel-collector-contract.mjs`、`make otel-check` |

## 5. Troubleshooting

| 症狀 | 可能原因 | 處置 |
|---|---|---|
| collector 啟動失敗 | receiver / exporter / pipeline 名稱不一致 | 先跑 `node scripts/check-otel-collector-contract.mjs` |
| API 無法送 trace | `OTEL_EXPORTER_OTLP_ENDPOINT` 與 Compose service name 不一致 | 確認 `otel-collector:4317` 與 `0.0.0.0:4317` |
| 正式環境無 trace backend | 本地只用 `debug exporter` | 在 deployment 文件明確替換 Tempo / Jaeger / OTLP backend |
| CI 無法抓到漂移 | 只檢查 Go tests，未檢查 YAML contract | 把 collector check 放入 root-course gate |

## 6. Best Practices

| 原則 | 說明 |
|---|---|
| instrumentation 與 collector 都要測 | 有 span 程式碼不代表 collector pipeline 可用 |
| 本地 exporter 保持低依賴 | 教學環境使用 `debug exporter`，避免要求額外 trace backend |
| 正式環境替換而非改壞 contract | 替換 exporter 時保留 receiver、endpoint、pipeline 與取樣策略說明 |
| trace 不取代 metrics | 先用 metrics 判斷影響範圍，再用 trace 定位單次 request |

## 7. Risk Notes

| 風險 | 狀態 |
|---|---|
| 正式 OTLP backend 未納入本 repo | 可接受；本 repo 只固定本地教學 collector contract |
| trace sampling policy 尚未成形 | 留待後續企業部署章節補強 |
| Docker Compose 不等於 Kubernetes | Compose contract 只證明本地端到端 wiring，不代表正式平台部署完成 |

## 8. Summary

本輪建議更新目標是 v1.0.33：補上 OTLP collector contract，使 OpenTelemetry 從「程式碼有 trace」提升為「collector config、Compose endpoint、runbook、README、CI 都有可重跑檢查」。

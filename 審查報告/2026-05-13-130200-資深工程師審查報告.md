## 1. 總體結論

目前教程已不再只是語法教學，整體深度已能支撐「由基礎語法進入 production service」的學習路線。主教材包含語法、資料結構、錯誤處理、併發、測試、效能、部署、依賴治理與第二階段 `production-api-worker`，廣度符合專案開發型教程要求。

從資深工程師角度看，`production-api-worker` 已逐步補齊 API contract、strict request decoding、request correlation、panic recovery、readiness/draining、queue shutdown safety、retry cancellation 與 request timeout contract。這些都是實務專案中比語法更容易被忽略、但會直接影響上線穩定性的工程面。

本輪仍發現一個明確缺口：**啟動設定尚未形成可測合約**。`cmd/api-worker/main.go` 目前透過 `envInt` 對 `QUEUE_SIZE`、`WORKERS` 做 silent fallback；`PORT` 也只以字串拼接進 `http.Server.Addr`。這會讓錯誤環境變數在部署時被悄悄改成預設值，導致 staging / production 實際容量、port、worker 數與設定檔不一致，排障時很難發現根因。

## 3. 需要更新的缺失

### P1：啟動設定 silent fallback 會掩蓋部署錯誤

目前 `envInt("QUEUE_SIZE", 64)` 與 `envInt("WORKERS", 4)` 在值不是整數或小於等於 0 時會直接回預設值。這在教學 demo 可以接受，但 production service 不應該讓錯誤設定靜默通過。

風險：

- Kubernetes / Docker Compose secret 或 env typo 不會讓服務 fail fast。
- `WORKERS=0`、`QUEUE_SIZE=-1` 等錯誤值會被改成預設值，容量規劃與實際行為不一致。
- `PORT` 若帶入不合法值，錯誤會延後到 `ListenAndServe`，且沒有統一設定錯誤訊息。
- 教材雖然談到 Configuration 管理，但可執行專案還沒有展示「設定也是合約」。

建議：

- 新增 `internal/config` package，集中讀取 `PORT`、`QUEUE_SIZE`、`WORKERS`、`DATABASE_URL`、`OTEL_EXPORTER_OTLP_ENDPOINT`。
- 對 `PORT` 驗證 1-65535，對 `QUEUE_SIZE` / `WORKERS` 驗證正整數。
- `cmd/api-worker` 啟動時先載入設定；設定錯誤直接 `log.Fatal`，避免服務以錯誤容量或錯誤 port 啟動。
- 新增 config unit tests，固定 default、合法 env 與不合法 env 的行為。

## 6. 風險備註

- 本輪應避免重做已完成的 API contract、panic recovery、request timeout 與 retry cancellation 主題。
- 本輪改動應保持最小：只把啟動設定從 silent fallback 改成可測、可文件化的 fail-fast contract。
- 若離線環境無法下載 `production-api-worker` 外部依賴，不應把 `go test ./...` 失敗誤判為程式邏輯失敗；需分別記錄 config package 可驗證結果與外部 module 下載限制。

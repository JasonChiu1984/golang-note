## Executive Summary

教材目前已具備完整 Go 語法、專案結構、production API worker、migration、observability、效能診斷、Release Note 與跨語言效能比較素材。以專案開發深度來看，已超出一般入門教材，接近「工程 onboarding + production service pattern」等級。

本輪主要缺口不是單一程式碼功能，而是 release gate 尚未完全落地：README、第 9 章、第 11 章與 `production-api-worker/README.md` 都描述了 CI/CD、race test、contract test、govulncheck 與 Docker build，但 repo 內沒有 `.github/workflows`。這會讓讀者知道要做 CI，卻無法直接參考一份與本專案匹配、可推到 GitHub 後自動執行的 workflow。

## 具體缺失

| 缺失 | 證據 | 風險 | 優先度 |
|---|---|---|---|
| GitHub Actions workflow 不存在 | `find .github -maxdepth 3 -type f` 無輸出 | 教材說明 CI，但 repo 不能在 PR / push 自動驗證 | P1 |
| `production-api-worker/Makefile` 缺少 CI 對齊 target | 只有 `test`、`test-race`、`run`、`migrate`、`docker-up/down` | 本機與 CI 執行指令容易漂移 | P1 |
| 整合 HTML 的 GitHub Actions 連結指向不存在路徑 | `../production-api-worker/.github/workflows/production-api-worker.yml` | GitHub Pages / 本地讀者點擊後無法找到 workflow | P2 |
| 第 9 / 11 章仍偏向範例型 CI 說明 | 章節有 YAML 範例與 CI 建議，但未指向 repo 內正式 workflow | 讀者難以分辨「教材範例」與「正式 gate」 | P2 |

## 風險備註

- `govulncheck` 需要 GitHub Actions runner 可下載工具與讀取 vulnerability database；離線環境不可宣稱通過，只能標記待補。
- `go-version: "1.26.x"` 是依 2026-05-13 官方 Go Release History 設定的教材基準；未來 Go 1.27 發布後需重新評估支援窗口與 runner OS。
- Docker build gate 可確認 image 可建置，但不等同完整 Postgres + OTLP runtime smoke test；後續可再拆出 compose integration gate。

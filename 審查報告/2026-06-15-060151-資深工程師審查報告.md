## 結論

教程針對專案開發的深度與廣度已符合 production-oriented Go 教材定位。`production-api-worker` 已覆蓋 HTTP API、OpenAPI、readiness、request decoding、body limit、CORS、API key security、rate limit、trusted proxy、HTTP timeout、startup config、DB pool、migration、worker failure、retry cancellation、queue backpressure、pprof、OTLP、Prometheus、Compose smoke、CI quality gate、CI contract parity、contract inventory 與 docs publishing gate。

本輪不建議擴張新的 runtime feature。較高價值缺口是 release hygiene：repo 內被 git 追蹤的 `production-api-worker/.github/workflows/production-api-worker.yml` 仍是獨立 production workflow 範本，但目前只固定 `go test ./...`、`go test -race ./...` 與 binary build，未與根目錄 `.github/workflows/ci.yml` 的 production release gate 對齊，也未被任何 static contract checker 保護。

## 主要缺失

### P1 - Standalone production workflow 缺少 contract-grade release gate

`production-api-worker/.github/workflows/production-api-worker.yml` 若被用於 production worker 獨立 repo 或子專案同步，會漏掉目前教材反覆強調的 release gate：

- `go mod download` / `go mod verify`
- `make ci-contract`
- `go test -race -cover ./... -count=1`
- `govulncheck ./...`
- Docker image build
- `docker compose up -d --build`
- host-side `scripts/compose-smoke.sh`
- failure 時輸出 `docker compose logs --no-color`
- always cleanup `docker compose down -v`

這和 `v1.0.53` 之後建立的 CI quality gate、`v1.0.54` 的 CI contract parity、`v1.0.55` 的 contract gate inventory，以及 `v1.0.58` 的 docs publishing contract gate 精神不一致。

### P2 - 缺少 static checker 防止 production workflow 再度退化

目前已有 27 個 root `scripts/check-*-contract.mjs`，但沒有 checker 會讀取 `production-api-worker/.github/workflows/production-api-worker.yml`。因此即使根目錄 CI 維持完整，tracked standalone workflow 仍可能被簡化成只跑 unit test，且 existing inventory gate 不會發現。

### P2 - 教材入口未把 standalone workflow 視為可驗證 artifact

README、production README、API contract、OpenAPI、第 7 / 9 / 11 章、進階 Cheat Sheet 與整合視覺課程已說明根目錄 `.github/workflows/ci.yml`，但沒有清楚標示 production standalone workflow 必須和根目錄 release gate 保持 parity。

## 建議修正

1. 新增 `scripts/check-production-workflow-contract.mjs`，固定 standalone workflow 需保留 production contract、race/coverage、govulncheck、Docker build、Compose smoke、failure logs 與 cleanup。
2. 將 `production-api-worker/.github/workflows/production-api-worker.yml` 升級為 production workflow contract gate，保留 path trigger，但補齊 contract-grade release steps。
3. 在 `production-api-worker/Makefile` 新增 `production-workflow-check`，並在根目錄 `.github/workflows/ci.yml` 新增 `Check production workflow contract`。
4. 同步 README、production README、API contract、OpenAPI、第 7 / 9 / 11 章、進階 Cheat Sheet、整合視覺課程與 contract gate inventory，版本升為 `v1.0.59`。
5. 依 release 流程同步 `docs/index.html`，建立「內容需要更新的部分」與「更新資料」，完成驗證後建立 annotated tag 並推送。

## 審查判斷

本輪屬於 release governance / traceability maintenance release。它不改動 production API runtime 行為，但會讓 tracked workflow artifact 與課程宣稱的 production release gate 一致，降低後續抽離子專案或複製 workflow 時的驗證落差。

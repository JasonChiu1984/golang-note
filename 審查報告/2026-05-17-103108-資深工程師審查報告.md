## Executive Summary

本教程在專案開發深度與廣度上已具備 production API、CI、Compose smoke、Release Note、效能比較、Assembly hot path、微服務與可觀測性等進階材料。v1.0.28 補齊 API security contract 後，下一個高價值缺口不是新增更多後端功能，而是把「語法應用圖解」從視覺展示提升為可維護的工程教學資產。

目前 `docs/golang-syntax-application-svg.html` 與 `圖解筆記3-4整合/golang-syntax-application-svg.html` 已開始改用標準程式流程圖符號，但 README 尚未把此品質要求納入 release gate，也缺少可重跑檢查，未來容易在手動修改 HTML 時退回一般插圖或遺漏 SVG metadata。

## Configuration Review

本輪不修改 runtime configuration。現有 production API 的 `API_KEY`、DB pool、migration、timeout、queue 與 Compose smoke 設定仍維持 v1.0.28 合約。新的設定型交付是 documentation gate：`node scripts/check-syntax-flow-svg.mjs`。

## Verification Review

本輪應新增並執行下列驗證：

| Gate | 目的 |
|---|---|
| `node scripts/check-syntax-flow-svg.mjs` | 確認 docs 與整合來源都保留 25 個 syntax flow、25 個 blueprint、標準流程圖符號與 SVG metadata |
| `node scripts/fix-docs-index-links.mjs --sync-source` | 重新同步 GitHub Pages 主入口並套用 docs-root link fix |
| `node scripts/fix-docs-index-links.mjs --check` | 確認 Pages 入口沒有 `/docs`、`/ReleaseNote` 或跨根目錄錯誤連結 |
| `node scripts/check-html-home-links.mjs` | 確認 HTML 補充頁可回到 docs 主頁 |
| `git diff --check` | 確認 Markdown / HTML / script 沒有 trailing whitespace 或 patch 格式問題 |

## Troubleshooting

| 症狀 | 可能原因 | 修正方式 |
|---|---|---|
| 語法圖解頁仍出現舊風格描述 | 手動改 docs 但未改整合來源，或反向同步覆蓋 | 同時更新 `docs/` 與 `圖解筆記3-4整合/`，再跑檢查腳本 |
| `docs/index.html` link 失效 | 直接複製整合課程後未套用 Pages link fix | 執行 `node scripts/fix-docs-index-links.mjs --sync-source` |
| SVG 無輔助說明 | renderer 未保留 `<title>` / `<desc>` | 檢查 `appendSvgMetadata` 與 `aria-labelledby` |

## Best Practices

1. 視覺教材只要成為主教材入口，就應有靜態品質檢查，不應只靠人工瀏覽。
2. 產生式 HTML 應把資料結構、renderer 與驗證腳本一起維護，避免單點手改漂移。
3. 每次修改 `docs/index.html` 都應先同步來源，再套用 link fix，最後跑 check mode。
4. 官方 Go 版本狀態仍需以 `go.dev/doc/devel/release` 為準；截至本報告時間，Go 1.26.3 / Go 1.25.10 為 2026-05-07 patch release。

## Risk Notes

- 本輪只處理教程視覺流程圖品質 gate，不變更 Go runtime 範例或 production API 行為。
- 現有工作樹含 `.vscode/settings.json` 與 `.codex-*.png` 等非本輪交付檔，發布時應避免納入。
- 若 GitHub DNS 或網路受限，需明確記錄 push/tag 是否成功，不可假設遠端已更新。

## 1. 總體結論

目前教程的專案開發深度已經明顯高於一般入門教材，具備兩條實作路線：

| 路線 | 目前定位 | 審查結論 |
|---|---|---|
| `project-concurrent-crawler` | 教學型大型專案，負責 worker pool、retry、parser/store abstraction | 符合第 7 章大型專案入門深度 |
| `production-api-worker` | production-leaning API + worker skeleton，負責 API contract、observability、graceful shutdown、queue safety | 符合進階專案廣度，但仍需持續補齊 operation-grade edge cases |

本輪審查沒有發現需要大規模重構的問題。最高價值、最小風險的缺口是：`production-api-worker/internal/app.Service` 的 deadlock retry backoff 使用固定等待，尚未把 `context` cancellation / deadline 當成可測合約。

## 2. 發現項目

| 優先級 | 項目 | 影響 | 建議處理 |
|---:|---|---|---|
| P1 | Deadlock retry backoff 未監聽 `ctx.Done()` | request timeout、client disconnect 或 shutdown context 取消後，service 可能仍繼續重試交易，延長資源占用，也可能產生不該存在的後續副作用 | 將 retry backoff 改成 `select` 監聽 timer 與 context，並新增取消路徑測試 |
| P2 | 教材已說明 transaction boundary，但缺少 retry cancellation 的教學段落 | 學生容易以為 retry 只要「最後成功」即可，忽略取消與關閉情境 | 在第 7 章、第 11 章、Cheat Sheet、康乃爾筆記與 `production-api-worker` README 補上 cancellation gate |
| P3 | GitHub Pages / docs 入口尚未同步完整視覺課程 HTML | `golang-complete-visual-course.html` 已存在，但 `docs/index.html` 尚未作為 docs 入口 | 依需求複製到 `docs/index.html` |

## 3. 修正方向

本輪採用最小安全修正：

1. `Service.withDeadlockRetry` 保留既有 3 次 retry 與短 backoff 策略。
2. 每次 deadlock 後的 backoff 改為 `time.NewTimer` + `select`。
3. 若 `ctx.Done()` 先發生，立即回傳 `ctx.Err()`。
4. 新增 `TestCreateJobStopsDeadlockRetryWhenContextCanceled`，固定取消後只呼叫一次交易、不 enqueue job。
5. 文件同步新增 retry cancellation 的架構、工作流程、驗證與風險說明。

## 4. 風險備註

| 風險 | 說明 |
|---|---|
| 錯誤分類 | 本輪維持 service 層回傳 `context.Canceled` / `context.DeadlineExceeded`，未擴大變更 HTTP handler 的錯誤 envelope |
| DB 整合驗證 | 本地受限環境可能無法下載 production-api-worker 依賴，因此完整 Postgres / OTLP 驗證仍需在可連網環境或已預載 module cache 的 CI 執行 |
| Git worktree | 此 linked worktree 過去有 index lock 權限限制，若一般 commit 失敗需使用臨時 Git index 流程 |

## 1. Overview

本輪從「是否能支撐專案開發深度與廣度」重新審查教材。v1.0.30 已補齊 operational runbook、Prometheus alert rules 與 incident workflow，教材的 production service 主線已具備可值班的基本骨架。

本輪最高價值缺口有兩個，且都屬於「把文件變成可驗證交付物」：

1. Prometheus 已有 alert rules，但缺本地 scrape config、`rule_files` 載入範本、Compose monitoring profile 與對應 gate。
2. API 合約已有 Markdown 與 Go contract tests，但缺 machine-readable OpenAPI artifact，前端、SDK、測試工具與文件生成無法共用同一份契約。

## 3. Workflow Review

目前 release workflow 已包含 root module tests、production API contract tests、race / coverage、Docker build、Compose smoke、operational runbook check 與 docs index link fix。

缺口是 Prometheus config 與 OpenAPI spec 尚未被納入 workflow。若未來有人刪掉 scrape job、改錯 rule file path、移除 endpoint schema 或漏掉 error code，CI 應該能在文件與合約層先攔下。

## 4. Configuration Review

| 項目 | 現況 | 缺失 |
|---|---|---|
| `configs/prometheus/production-api-worker-alerts.yml` | 已有 5 條教學用 alert rules | 缺載入它的 Prometheus config |
| `/metrics` endpoint | 可被 scrape，`API_KEY` 啟用後受 Bearer token 保護 | 需明確標註 local profile 與正式 scrape auth 差異 |
| `docker-compose.yml` | 有 Postgres、OTel collector、API、migration | 缺可選 Prometheus service profile |
| `docs/api-contract.md` | 有人讀的 API 合約 | 缺 `production-api-worker/api/openapi.yaml` |
| CI gate | 有 runbook check | 缺 Prometheus config check 與 OpenAPI contract check |

## 5. Verification Review

本輪建議新增兩個低成本檢查腳本：

| 檢查 | 目的 |
|---|---|
| `scripts/check-prometheus-config.mjs` | 固定 scrape job、rule_files、Compose monitoring profile、README、runbook 與 CI 入口 |
| `scripts/check-openapi-contract.mjs` | 固定 OpenAPI version、endpoint、schema、error code、Bearer auth、`X-Request-ID` 與 CI 入口 |

## 6. Troubleshooting Review

| 症狀 | 需要補的處置 |
|---|---|
| Prometheus targets 顯示 down | 查 API service、Compose profile、`/readyz`、`/metrics` |
| alert rules 沒載入 | 檢查 `rule_files` mount path 與 Prometheus UI rules |
| `/metrics` 回 401 | 說明 `API_KEY` 與 scrape auth 的關係，不把 secret 寫進 repo |
| OpenAPI schema 漂移 | 用 check script 對照 endpoint、error code 與 request/response schema |
| CI 沒抓到文件漂移 | 將 Prometheus config / OpenAPI checks 加入 root-course job |

## 7. Best Practices

1. Alert rules 必須有 scrape config 與 rule loading 範本，否則只是文件片段。
2. 教學 profile 可用 `API_KEY` 空值啟動，但正式環境要使用 bearer token file 或平台 secret。
3. API 合約需同時有人讀的 Markdown、機器讀的 OpenAPI、以及 Go contract tests。
4. Prometheus config、alert rules、runbook、OpenAPI spec 與 README 需一起維護。

## 8. Risk Notes

| 風險 | 說明 |
|---|---|
| 本地 Prometheus 不等於正式監控 | Compose profile 僅作教學與驗證，不代表企業監控已部署 |
| API key scrape auth 未自動化 | 正式環境需自行配置 bearer token file 或 secret mount |
| OpenAPI 不是 runtime 驗證器 | 本輪固定合約 artifact，不取代 Go contract tests |
| Docker daemon 依賴 | 本地 profile 啟動仍需 Docker；靜態 config check 不依賴 Docker |

## 9. 審查結論

本輪應新增 Prometheus scrape config、Compose `monitoring` profile、Prometheus config check、OpenAPI 3.1 spec、OpenAPI contract check，並同步 README、production README、API contract、runbook、章節、整合視覺課程與 CI。這是 v1.0.30 runbook gate 之後最小且高價值的 production handoff 補強。

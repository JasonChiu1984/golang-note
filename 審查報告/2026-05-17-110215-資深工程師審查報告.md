# Golang 學習筆記資深工程師審查報告

> 審查日期：2026-05-17
> 完整日期時間：2026-05-17 11:02:15 CST +0800
> 審查版本基準：v1.0.29
> 審查者視角：資深 Go / 後端 / production service 工程師

## 1. Overview

本輪從「能否支撐專案開發深度與廣度」重看教材。v1.0.29 已把 Go 語法應用圖解固定成 SVG 流程圖品質門檻，教材的語法、併發、API、DB、CI、security、migration 與效能補充已經具備主教材深度。

本輪最高價值缺口不在語法或 API contract，而在 production observability 尚未形成可交付 runbook：教材有 log / metrics / trace / health 的概念與程式接線，但缺少 SLI/SLO、Prometheus alert rules、incident workflow、verification 與 risk notes 的固定 artifact。

|---|---|---:|---|
| Go 語法與心智模型 | 章節、速查、視覺課程與語法 SVG 流程圖完整 | 9/10 | 足以支撐日常 Go 開發與教學 |
| 可執行專案 | `project-concurrent-crawler` 與 `production-api-worker` 串起學習路線 | 9/10 | 已從 toy example 升級為 production-shaped example |

## 3. Workflow Review

目前 workflow 從開發到 release 已具備：

1. root examples / crawler tests。
2. production API contract tests。
3. race / coverage。
4. Docker build。
5. Compose smoke。
6. docs index link fix。

缺口是 incident workflow 仍散落在章節敘述。當 `api_requests_total` 5xx 升高、`worker_queue_depth` 堆積、`worker_job_duration_seconds` p95 升高或 `/metrics` 消失時，教材尚未給出固定處置順序與可重跑檢查。

## 4. Configuration Review

| 項目 | 現況 | 缺失 |
|---|---|---|
| `API_KEY` | 已保護 `/jobs` 與 `/metrics` | 需要提醒 Prometheus scrape auth 風險 |
| `QUEUE_SIZE` / `WORKERS` | 已 fail-fast 驗證 | 需要以 queue depth 告警連到容量判斷 |
| DB pool | 已由 env 設定 | 需要在 latency / queue 告警時列入排查 |
| `OTEL_EXPORTER_OTLP_ENDPOINT` | 可接 OTLP 或 stdout | 需要說明 trace backend 未部署時的限制 |
| Prometheus alert rules | 無 repo 內 artifact | 需要新增 `configs/prometheus/production-api-worker-alerts.yml` |

## 5. Verification Review

本輪建議新增一個低成本檢查腳本，固定下列事項：

| 檢查 | 目的 |
|---|---|
| runbook 存在 | 避免 observability 教材只剩概念 |
| alert rules 存在 | 避免 SLI/SLO 沒有 Prometheus rule 範例 |
| README 入口存在 | 讓主教材與 production 範例都找得到 runbook |
| CI workflow 有 gate | 避免未來更新移除 runbook 而 CI 不知道 |

## 6. Troubleshooting Review

教程目前有受限環境、module proxy、dyld、govulncheck 等排錯說明，但 production incident 題型仍應補齊：

| 症狀 | 需要補的處置 |
|---|---|
| 5xx rate 升高 | 依 route / method / status 找範圍，再用 `X-Request-ID` 查 log / trace |
| queue depth 升高 | 同時檢查 worker latency、DB pool、CPU throttling 與 worker 數 |
| worker p95 latency 升高 | 不先盲目加 goroutine，先保留 benchmark / metrics 證據 |
| metrics missing | 檢查 `/metrics` API key、scrape config、readiness 與部署狀態 |

## 7. Best Practices

1. Observability 不只是在程式中註冊 metrics，還要有告警與值班流程。
2. Metrics label 必須維持低基數，`/jobs/{id}` 不可展開成實際 job id。
3. Alert rule 必須有 `severity`、`summary`、`description` 與 `runbook_url`。
4. Incident 後應回補 contract test、smoke gate 或 runbook gate。
5. 教學用 threshold 不可宣稱為正式 SLA，需標註風險與調整方式。

## 8. Risk Notes

| 風險 | 說明 |
|---|---|
| Prometheus rule 未部署 | repo 內 rule 只能證明教材與範例完整，不代表真實 Alertmanager 已上線 |
| 閾值屬教學 baseline | 2%、5%、2s、50 queue depth 需依真實流量重算 |
| Trace backend 未固定 | stdout exporter 適合教學，正式環境需接 collector / backend |
| Compose 不等於 K8s | Compose smoke 可證明端到端鏈路，但不取代 Kubernetes rollout policy |

## 9. 審查結論

本輪應新增 `production-api-worker` operational runbook、Prometheus alert rules 與 runbook check script，並將 README、production README、章節、整合 HTML 與 CI workflow 同步更新。此修正比再新增語法素材更符合目前教材的下一個工程深度缺口。

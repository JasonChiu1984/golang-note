## 二、官方版本基準

Go 官方 release history 目前列出：

- `go1.26.3`：released 2026-05-07，包含 `go` command、`pack` tool、`html/template`、`net`、`net/http`、`net/http/httputil`、`net/mail`、`syscall` 等安全修正與多項 bug fix。
- `go1.25.10`：同日發布，仍屬受支援分支。
- Go 1.26 release notes 明確提到：Go 1.26 需要 Go 1.24.6+ 才能 bootstrap；Go 1.26 是最後支援 macOS 12 Monterey 的版本；Go 1.27 將要求 macOS 13+；`windows/arm` 已移除；`freebsd/riscv64` 標記 broken；`linux/riscv64` 支援 race detector；Wasm 的 `GOWASM=signext/satconv` 設定已被忽略。

來源：

- https://go.dev/doc/devel/release
- https://go.dev/doc/go1.26

## 三、發現的教材缺口

| 優先級 | 發現 | 影響 | 建議 |
|---|---|---|---|
| P1 | 第 1 章支援平台仍停在一般性列表，未說明 Go 1.26 平台生命週期 | 學員可能以為 `go tool dist list` 內所有平台都可無條件作為 production release target | 補上 Go 1.26 bootstrap、macOS、Windows ARM、FreeBSD/RISC-V、Wasm 與 race detector 注意事項 |
| P1 | 第 9 章部署流程未把 Go 1.26 toolchain 升級做成 release gate | 實務專案可能只改 `go.mod`，卻漏改 Docker builder、GitHub Actions、Makefile release matrix | 新增 Go 1.26 Docker/CI 升級清單 |
| P2 | 康乃爾第 9 章仍使用 `golang:1.22-alpine` 作為 Docker builder 範例 | 摘要筆記與主教材 Go 1.26.3 基準不一致 | 改成 `golang:1.26-alpine` 並補充同步 CI/Docker |
| P2 | 教材把 Go binary 描述為靜態部署優勢，但未充分提醒 CGO 例外 | 初學者可能誤以為所有 Go binary 都可直接放進 `scratch` | 補上 `CGO_ENABLED=0` 優先但需 `ldd` / `otool -L` / smoke test 驗證 |

## 四、本輪修正策略

本輪採取最小、安全、文件型修正：

1. 不新增新專案或新依賴。
2. 不改動 `go.mod` 的 `go 1.22` 相容層。
3. 補強 README、第 1 章、第 9 章與康乃爾摘要，讓 production 升級決策完整。
4. 版本號提升為 `v1.0.6`，並在 CHANGELOG 與更新紀錄中標明修改範圍。

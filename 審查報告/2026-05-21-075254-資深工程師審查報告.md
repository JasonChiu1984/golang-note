## 1. Overview

本教程已具備從語法、併發、專案架構、OpenAPI、CI、Docker Compose、observability、pprof、CORS、request body limit 與 HTTP server timeout 的完整主線。以專案開發深度與廣度來看，已超過一般入門教材，接近「可用 production service 範例驅動的 Go 工程教材」。

本輪重看後，v1.0.39 的 HTTP server timeout contract 已把 slow client、read/write timeout、shutdown timeout 與 queue drain timeout 固定成可測合約。下一個高價值缺口不是新增大型功能，而是把已存在於程式、OpenAPI 與測試中的 `X-Request-ID` request correlation 明確升級成獨立 release gate。

## 3. Workflow 審查

目前教學 workflow 已從「會寫 Go」延伸到「能驗收 production contract」：

1. 寫 handler / service / worker。
2. 用 Go contract tests 固定 status code、JSON、header、錯誤碼。
3. 用 OpenAPI 固定 machine-readable contract。
4. 用 Node static check 固定文件、測試、CI 與實作的關聯。
5. 用 docs/index.html 作為 GitHub Pages 入口。

缺失是 request correlation 仍主要散落在 API contract、README 與 tests 中，尚未像 CORS、rate limit、body limit、HTTP timeout 一樣有獨立 `scripts/check-*.mjs` gate。

## 4. Configuration 審查

本輪不需要新增 env 參數。`X-Request-ID` 屬於 HTTP header / middleware contract，不應變成可關閉設定，否則 incident triage 會因部署設定漂移而失去關聯能力。

## 6. Troubleshooting 審查

| 風險 | 可能症狀 | 建議修正 |
|---|---|---|
| request id 只回 response header | log / trace 查不到同一 id | 靜態 gate 必須檢查 `requestIDFromContext` 與 `request.id` |
| OpenAPI 漏掉 header | 前端 mock / SDK 不知道要帶 `X-Request-ID` | 靜態 gate 必須檢查 OpenAPI RequestID parameter / header |
| CI 未跑 gate | 文件更新後又漂移 | `.github/workflows/ci.yml` 需新增檢查步驟 |
| 教材只提 observability 概念 | 讀者不知道如何驗收 | README、章節、Cheat Sheet 與整合 HTML 需提供明確指令 |

## 7. Best Practices

- request id 不應只存在於 log，必須同時出現在 response header、request context 與 trace attribute。
- `X-Request-ID` 若由 client 提供，server 應原樣回傳，方便跨系統 incident ticket 對照。
- 未提供時由 server 產生 `req-*`，避免匿名 request 在排障中失去索引。
- request correlation 是 release contract，不是單一 middleware 實作細節；應納入 static gate 與 CI。

## 8. Risk Notes

- 本輪不新增 runtime 行為，主要是文件、OpenAPI、CI 與 static gate 收斂，風險低。
- 本輪不處理正式分散式 trace backend、log aggregation 或 API gateway correlation header policy；這些屬於更高階部署拓撲題。
- 若未來導入 gateway，需明確定義 gateway 是否覆寫或傳遞 `X-Request-ID`。

## 9. 結論

本教程整體深度與廣度符合進階專案開發教材要求。本輪最小且高價值的更新是新增 `Request correlation contract gate`，把已存在的 `X-Request-ID` 行為正式版本化並納入 CI，避免 observability correlation 在後續 handler / OpenAPI / 文件重構時退化。

## Executive Summary

目前教程已從語法教學擴展到可執行 production service：API 合約、CORS allowlist、request body limit、rate limit、pprof、OTLP、Prometheus、shutdown signal、DB pool 與 migration 都已具備文件、測試與部分 CI gate。以專案開發深度來看，已符合中高階 Go 教程需求。

本輪最高價值缺口是 HTTP server timeout 尚未形成正式 contract。`api-worker` 已設定 `ReadHeaderTimeout`，但 read body、write response、idle keep-alive、HTTP shutdown 與 queue drain timeout 仍沒有集中 config、fail-fast 驗證與獨立測試。這會讓 slow client、卡住的 response 或 rolling deploy drain 時間不可預測，和目前教材強調的 production-ready 方向不一致。

## 主要發現

| 優先級 | 發現 | 影響 | 建議 |
|---|---|---|---|
| P1 | HTTP server timeout 尚未成為版本化 contract | slowloris、慢速 body、write blocking、keep-alive 佔用與 shutdown drain 時間不可預測 | 新增 `HTTP_READ_HEADER_TIMEOUT`、`HTTP_READ_TIMEOUT`、`HTTP_WRITE_TIMEOUT`、`HTTP_IDLE_TIMEOUT`、`HTTP_SHUTDOWN_TIMEOUT`、`QUEUE_DRAIN_TIMEOUT` |
| P1 | `main.go` 目前只明確設定 `ReadHeaderTimeout` | 教材讀者可能以為只設定 header timeout 已足夠 | 將所有 timeout 由 config 套用到 `http.Server` 與 shutdown flow |
| P2 | CI 缺少 HTTP timeout 靜態檢查 | 文件、config、main 與測試可能逐步漂移 | 新增 `scripts/check-http-timeout-contract.mjs` 與 `make http-timeout-check` |
| P2 | 教材章節與整合 HTML 尚未標示 timeout 操作合約 | production API 章節少了 slow client / drain timeout 的風險教育 | 更新 README、章節 7/11、Cheat Sheet、整合視覺課程與 API contract |

## 建議修正範圍

1. 設定層新增 HTTP timeout / queue drain timeout 預設值與 env parsing。
2. config tests 覆蓋預設值、合法 override 與不合法 duration fail-fast。
3. `cmd/api-worker` 新增 `serverTimeouts` helper，集中套用到 `http.Server` 與 shutdown / queue drain。
4. 新增 `TestHTTPServerTimeoutContract` 固定啟動入口的 timeout contract。
5. 新增靜態檢查 script、Makefile target 與 GitHub Actions gate。
6. 更新 README、API contract、章節、Cheat Sheet、整合視覺課程、VERSION、CHANGELOG 與 docs/index.html。

## 風險說明

| 風險 | 說明 | 控制方式 |
|---|---|---|
| timeout 過短 | 正式 workload 若 body 或 response 合理較長，可能造成 premature timeout | 預設採保守教學值，允許 env override |
| timeout 過長 | slow client 仍可能佔用連線 | CI 固定所有 timeout 必須存在並可調 |
| shutdown drain 過短 | 長任務可能被迫中止 | `QUEUE_DRAIN_TIMEOUT` 獨立於 HTTP shutdown，可依部署環境調整 |

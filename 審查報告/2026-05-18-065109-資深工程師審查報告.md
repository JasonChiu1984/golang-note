## 3. Workflow

Shutdown workflow 應固定為：

```text
SIGINT / SIGTERM
-> readiness = draining
-> http.Server.Shutdown(ctx)
-> queue.ShutdownContext(ctx)
-> timeout 後 forced cancel
```

Rate limit client identity workflow 應固定為：

```text
RemoteAddr in TRUSTED_PROXY_CIDRS?
-> yes: use first X-Forwarded-For IP
-> no: use TCP RemoteAddr host
-> apply RATE_LIMIT_REQUESTS_PER_MINUTE
-> over limit: 429 rate_limited + Retry-After
```

CORS workflow 應固定為：

```text
Origin empty
-> continue without CORS headers
Origin in CORS_ALLOWED_ORIGINS
-> set Access-Control-Allow-Origin + Vary: Origin
OPTIONS preflight allowed
-> 204 No Content
OPTIONS preflight not allowed
-> 403 Forbidden
```

## 4. Configuration

| 設定 | 預設 | 合約 |
|---|---|---|
| `RATE_LIMIT_REQUESTS_PER_MINUTE` | `120` | 必須為正整數 |
| `TRUSTED_PROXY_CIDRS` | 空字串 | comma-separated CIDR；空值時不信任 `X-Forwarded-For` |
| `CORS_ALLOWED_ORIGINS` | 空字串 | comma-separated exact http/https origins；不可包含 path、query 或 fragment |
| Signal set | 無 env | `api-worker` 必須包含 `os.Interrupt` 與 `syscall.SIGTERM` |

`TRUSTED_PROXY_CIDRS` 僅應填入 Nginx、Envoy、API Gateway、Kubernetes ingress 或 load balancer 的內部 CIDR。服務直接暴露時保持空值，避免外部 client 自行送 `X-Forwarded-For` 繞過限速。

## 6. Troubleshooting

| 症狀 | 可能原因 | 建議處理 |
|---|---|---|
| Kubernetes rolling deploy 後 request 被中斷 | 服務未監聽 `SIGTERM` 或 readiness 未先轉 draining | 檢查 `monitoredSignals()` 與 `/readyz` draining 流程 |
| Ctrl+C 可以關閉但 Docker stop 行為異常 | 只測了 `SIGINT`，未測 `SIGTERM` | 跑 `TestMonitoredSignalsContract` |
| rate limit 可被換 `X-Forwarded-For` 繞過 | 未限制 trusted proxy 來源 | 保持 `TRUSTED_PROXY_CIDRS` 空值，或只加入內部代理 CIDR |
| Browser preflight 回 403 | Origin 未列入 `CORS_ALLOWED_ORIGINS` | 加入 exact origin，不要加入 path、query、fragment 或 wildcard |
| 設定錯誤卻能啟動 | CIDR 未 fail fast 驗證 | 跑 `go test ./internal/config -count=1` |

## 7. Best Practices

- `cmd/` 層應負責 signal、config 與 dependency wiring，不應把 signal set 隱含成不可測的啟動細節。
- graceful shutdown 文件必須明確區分 local Ctrl+C 與 container runtime / orchestrator 的 `SIGTERM`。
- 任何使用 `X-Forwarded-For` 的 production service 都必須有 trusted proxy allowlist。
- 任何由瀏覽器呼叫的受保護 API 都應使用 exact CORS allowlist，不應以 `*` 搭配認證或敏感 response。
- rate limit key、OpenAPI、runbook、README 與 CI 應一起更新，避免教材只描述概念但缺少退化防護。

## 8. Risk Notes

本輪修正可在本地透過單元測試與靜態檢查完成，不需要外部服務。正式環境仍需搭配 load balancer readiness policy、Kubernetes termination grace period、Docker stop timeout、代理層 header 清理與 worker drain timeout 設定，才能形成完整部署安全邊界。

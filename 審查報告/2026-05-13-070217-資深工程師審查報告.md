# 2026-05-13 07:02 資深工程師審查報告

> 教材版本目標：v1.0.10  
> 教材基準：Go 1.26.3  
> 審查角度：專案開發深度、production readiness、可測試性、教程內部一致性

## 審查結論

此教程目前已具備完整 Go 專案開發主線：基礎語法、標準庫、併發、模組治理、部署、效能診斷、進階測試，以及兩個實戰專案 `project-concurrent-crawler` 與 `production-api-worker`。以資深工程師角度看，深度與廣度已符合「從語法到 production service」的教材定位。

本輪仍發現一個應補強的 production 缺口：`production-api-worker` 已經有 Prometheus metrics、OpenTelemetry tracing、`slog` 與 API contract test，但 request correlation 尚未落成可測試合約。若沒有穩定 `X-Request-ID`、structured log 欄位與 trace attribute，真實 incident review 很難從使用者回報的 response 對回單筆 log 與 span。

## 具體證據

| 檢查面 | 現況證據 | 判斷 |
|---|---|---|
| 專案廣度 | `README.md` 已列出 11 章、附錄、速查表、康乃爾筆記、兩個專案 | 合格 |
| 專案深度 | `production-api-worker` 具備 API、service transaction、repository、bounded queue、metrics、tracing、Docker Compose、CI | 合格 |
| API 合約 | `production-api-worker/docs/api-contract.md` 與 `internal/api/handler_test.go` 已固定 success/error schema | 合格 |
| 觀測性關聯 | `internal/api/handler.go` 有 metrics middleware 與 trace span，但未固定 `X-Request-ID` header 或 request-scoped logger | 需更新 |
| 教材一致性 | 第 5 章已介紹 Request ID middleware；第 7 章 production 專案尚未把它落到範例與合約 | 需更新 |

## 需要更新的部分

1. 在 `production-api-worker` API middleware 補上 `X-Request-ID` 保留與自動產生策略。
2. 將 request id 放入 request context、structured log 欄位與 trace attribute。
3. 用 contract test 固定 client-provided request id 原樣回傳，以及 server-generated request id 的格式。
4. 更新 API contract 文件，明確把 request correlation header 視為外部操作合約。
5. 更新 README、第 7 / 11 章、進階 Cheat Sheet、康乃爾筆記，讓教材文字與範例實作一致。

## 不納入本輪的項目

| 項目 | 原因 |
|---|---|
| 新增完整 distributed tracing backend 教學 | 需要外部服務與更大篇幅，不適合本輪最小安全修正 |

| 強制要求全 repo Go 1.26 toolchain | 本機仍是 Go 1.22.2，Go 1.26 新特性維持文件層級標示 |

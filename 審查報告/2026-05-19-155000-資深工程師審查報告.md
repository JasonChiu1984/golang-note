## Overview

本輪以資深工程師角度重新檢查教程的專案開發深度與廣度。整體教材已超過一般 Go 語法教學，具備 production service 的 handler、service、repository、worker、migration、observability、OpenAPI、CORS、rate limit、shutdown 與 CI gate。

主要缺口不是語法量不足，而是 HTTP input boundary 尚未被正式版本化：`decodeJobInput` 雖已使用 `http.MaxBytesReader`，但 1 MiB 限制仍屬隱含實作細節，沒有 env 設定、OpenAPI error code、contract test、CI script 與教程章節共同保護。

## Findings

| 優先級 | 發現 | 影響 | 建議 |
|---|---|---|---|
| P1 | Request body size limit 是隱含常數，不是部署設定 | 大型 payload 風險無法由部署環境調整，也不容易在 release note 追蹤 | 新增 `REQUEST_BODY_LIMIT_BYTES`，預設 1048576 bytes |
| P1 | Oversized payload 沒有獨立 API error code | client 無法區分 JSON 格式錯誤與 body 過大 | 超限固定回 `413 payload_too_large` |
| P2 | OpenAPI / API contract 未列出 413 response | 前端 mock、SDK 或 gateway review 會漏掉此錯誤分支 | 更新 OpenAPI 與 Markdown API contract |
| P2 | CI 尚未固定 request body limit 教程入口 | 後續文件或重構可能移除該行為而無警訊 | 新增 `scripts/check-request-body-limit-contract.mjs` 與 workflow step |
| P3 | 主教程已有 request body size 字眼，但沒有對應可執行 gate | 讀者知道概念，卻不知道如何驗證 | 更新 README、第 7 / 11 章、Cheat Sheet、整合 HTML |

## Configuration

| Env | 預設 | 規則 | 用途 |
|---|---:|---|---|
| `REQUEST_BODY_LIMIT_BYTES` | `1048576` | 正整數 byte 數 | 限制 `POST /jobs` request body |

錯誤設定如 `REQUEST_BODY_LIMIT_BYTES=0` 必須 fail fast，不可 silent fallback。

## Troubleshooting

| 症狀 | 可能原因 | 處理 |
|---|---|---|
| `413 payload_too_large` | request body 超過 `REQUEST_BODY_LIMIT_BYTES` | 調整 client payload 或部署 env |
| 啟動失敗並提示 `REQUEST_BODY_LIMIT_BYTES must be a positive integer` | env 設為 0、負數或非數字 | 改為正整數 byte 數 |
| OpenAPI check 失敗 | 版本或 `PayloadTooLarge` response 未同步 | 同步 `api/openapi.yaml` 與 `docs/api-contract.md` |

## Best Practices

- HTTP body limit 應在 decoder 前處理，不要等到 domain validation 才拒絕。
- `413 payload_too_large` 應與 `400 invalid_input` 分開，讓 client 能做正確 retry / UI 分支。
- 教程中的 production contract 應同時具備：設定、實作、測試、文件、OpenAPI、CI gate。
- 預設值要保守，正式部署再依 API gateway、Ingress、WAF 與業務 payload 大小調整。

## Risk Notes

- 本輪是 local-verifiable contract 更新，未執行真實外部流量壓測。
- Docker runtime smoke 需要本機 Docker daemon；若環境無 daemon，只能保留靜態與 Go test 驗證。
- `govulncheck` / module proxy 類檢查可能受網路限制，不能在失敗時標記為已通過。

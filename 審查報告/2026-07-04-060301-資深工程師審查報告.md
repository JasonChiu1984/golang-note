## 3. 內部缺失

### P1：Operational runbook scope freshness 未被正式 gate 固定

`production-api-worker/docs/operational-runbook.md` 的文件日期與完整日期時間仍是 2026-05-17，首段適用範圍沒有明確列入近期新增的 release governance / supply chain / docs publishing / API contract scope coverage。雖然 runbook 內文已提到 Supply chain artifact governance contract gate，但文件 metadata 與 verification table 沒有被 root contract checker 版本化固定。

風險：後續讀者會誤以為 runbook 只涵蓋早期 observability / Compose smoke，無法從 runbook 首段判斷它已經是正式 release governance 文件；新 gate 也可能只更新 README / OpenAPI / visual course，漏掉 runbook scope。

### P2：`scripts/check-operational-runbook.mjs` 仍偏向舊式完整性檢查

現有 `scripts/check-operational-runbook.mjs` 檢查 SLI / SLO、Prometheus alert、README 入口與 CI 步驟，但不是 root `check-*-contract.mjs` inventory 的一部分，也沒有要求版本、完整日期時間、近期 governance terms、Makefile target 與 GitHub Actions contract step 一起對齊。

風險：runbook 的基本內容存在時檢查會通過，但 release governance scope 漂移不會被 contract inventory 擋下。

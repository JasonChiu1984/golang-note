## 1. 結論

本教程已具備中高階 Go 專案教學深度：從語法、資料結構、併發、測試、效能、部署，到 `production-api-worker` 的 API contract、request decoding、request id、readiness/drain、panic recovery、request timeout、retry cancellation、queue shutdown 與 startup config，都已形成可執行範例與 release gate。

本輪仍可補強的最高價值缺口是 **Postgres connection pool contract**。目前 `production-api-worker/internal/repository/postgres.go` 將 `SetMaxOpenConns(25)`、`SetMaxIdleConns(10)`、`SetConnMaxLifetime(30 * time.Minute)` 寫死在 repository 層。這讓讀者容易誤解 production 容量是程式碼常數，而不是由部署環境、DB `max_connections`、worker 數、API 併發與維運策略共同決定。

## 3. 缺失與需要更新部分

| 缺失 | 影響 | 建議修正 |
|---|---|---|
| Postgres pool 設定硬編碼在 repository | staging / production 無法依 DB 容量與 worker 數調整連線池，且教材示範的 repository 承擔了部署設定責任 | 新增 `DATABASE_MAX_OPEN_CONNS`、`DATABASE_MAX_IDLE_CONNS`、`DATABASE_CONN_MAX_LIFETIME` |
| idle connection 數量未驗證 | `MaxIdleConns > MaxOpenConns` 類錯誤可能到執行期才暴露 | 在 config loader fail fast |
| lifetime duration 未形成設定合約 | 不同環境的 DB proxy、NAT、firewall idle timeout 需求不同 | 用 `time.ParseDuration` 驗證正數 duration |
| 教材未明確說明 DB pool 是 deployment contract | 讀者可能只學到 API/queue 設定，忽略 DB 容量與資源保護 | 更新 README、第 7 / 11 章、Cheat Sheet、康乃爾筆記與 `production-api-worker` 文件 |

## 4. 修正範圍建議

1. 在 `production-api-worker/internal/config` 新增 DB pool 欄位與預設值。
2. 在 config unit test 固定預設值、合法 env、idle/open 關係與 duration 解析錯誤。
3. 在 `production-api-worker/internal/repository` 新增 `PoolConfig`，讓 Postgres pool 由 `cmd/api-worker` 注入。
4. 更新教材與 release gate，讓 DB pool 成為 startup configuration contract 的一部分。
5. 保持 `DATABASE_URL` 空字串時使用 memory store 的既有行為，不擴大改動範圍。

## 6. 風險備註

- 本輪不應引入新的資料庫 driver 或外部套件。
- 不應把 DB pool 設定放到 repository 自行讀 env，否則會破壞 `cmd/` 負責 wiring 的教材主線。
- 若受限環境無法下載 Prometheus / OpenTelemetry / pgx 依賴，應明確記錄測試受阻原因，不可標示 full production-api-worker 測試已通過。
- 既有 `ReleaseNote/index.html` 工作樹已有未提交改動，本輪不應覆蓋或納入與 DB pool 無關的 release-note 版面差異。

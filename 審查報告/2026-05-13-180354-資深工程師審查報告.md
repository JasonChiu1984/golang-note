## 1. 整體判斷

本教程目前已符合「專案開發深度與廣度」要求：主線包含 Go 語法、資料結構、併發、project-concurrent-crawler、production-api-worker、API contract、observability、lifecycle、DB pool、migration contract、測試與部署 gate。v1.0.21 已補齊 Go 1.2-1.26 ReleaseNote 官方段落覆蓋，專案實務深度已足夠。

本輪重新審查後，最高優先缺口轉為「版本演進入口完整性」。ReleaseNote 已有 Go 1.2-1.26 專業報告，但少了 Go 1.1 這個 Go 1 compatibility 後第一個大型版本，導致早期基礎期的 `-race`、method values、Go 1.1 performance、`bufio.Scanner`、`go1.1` build tag 與相容性風險沒有進入同一套索引與 Pages 交付。

官方 Release History 本輪確認 Go 1.26.3 與 Go 1.25.10 都於 2026-05-07 發布，且官方 Release Policy 仍是「每個 major Go release 支援到已有兩個更新 major release 為止」。因此目前索引需要明確標示 Go 1.25 / Go 1.26 為支援窗口，Go 1.1-Go 1.24 為未支援版本，避免讀者把歷史 release note 誤當成可直接採用版本。

## 3. 主要缺失

### P1 - ReleaseNote 缺少 Go 1.1 起點

Go 1.1 是 Go 1 compatibility 後第一個大型版本，官方文件明確涵蓋 performance 30%-40%、race detector、method values、return requirement、64-bit `int`、Unicode surrogate、go command、go test profile 與 build constraints。若索引從 Go 1.2 開始，讀者會缺少早期工程演進的第一個基準點。

| 影響 | 風險 |
|---|---|
| Roadmap 起點不完整 | 早期基礎期無法完整說明 race detector 與 Go 1 compatibility 後的演進 |
| 效能脈絡缺失 | Go 1.1 performance 30%-40% 無法與後續 PGO / GC / compiler 改善串起 |
| 相容性教育不足 | `int` 64-bit、Unicode surrogate、untagged composite literal 等歷史風險未被納入教材 |

### P1 - ReleaseNote 索引缺少支援狀態視覺化

官方 Release Policy 屬於升級治理資訊，不應只在文字中提及。缺少支援狀態圖表時，讀者容易把 Go 1.24 或更早 release note 誤判為仍在官方維護窗口內。

## 6. 風險註記

- 本輪使用官方 Go Release History 與 Go 1.1 Release Notes 作為版本狀態與 Go 1.1 內容依據；若 go.dev 之後發布 Go 1.26.4 或 Go 1.27，需重新跑官方來源檢查。
- 本輪新增的是歷史 release-note 教材、支援狀態圖表與補充 HTML 頁，不宣稱本地專案已完成 Go 1.26 toolchain migration。
- Go 1.1 是歷史版本，教材用途是理解演進與升級治理，不建議新專案採用。

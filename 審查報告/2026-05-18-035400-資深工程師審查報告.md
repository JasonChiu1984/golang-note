## 1. Overview

本教程目前已具備 Go 語法、專案架構、API 合約、OpenAPI、Prometheus、pprof、OTLP、rate limit、CI 與 Docker Compose smoke gate，深度已接近 production service 教材。以資深工程師角度重新檢視後，本輪最高價值且最小風險的缺口是：文件已宣告 graceful shutdown 會處理 `SIGINT/SIGTERM`，但 `api-worker` 啟動程式缺少可測的 shutdown signal contract；同時 rate limit 在反向代理後方需要明確的 trusted proxy client IP 邊界，避免未信任來源用 `X-Forwarded-For` 偽造 rate limit key。

此缺口會讓教材在 local Ctrl+C 情境看似正確，但在 Docker Compose、Kubernetes 或 rolling deploy 發出 `SIGTERM` 時，可能未走入 readiness draining、HTTP shutdown 與 queue drain 的正式流程。

## 3. Workflow

建議 shutdown workflow 固定為：

```text
SIGINT / SIGTERM
-> readiness = draining
-> http.Server.Shutdown(ctx)
-> queue.ShutdownContext(ctx)
-> timeout 後 forced cancel
```

這個順序避免兩類 production 風險：第一，部署系統送出 `SIGTERM` 後服務未進入 draining；第二，process 直接退出導致 queue 裡已接受的 job 沒有完成或沒有可觀測紀錄。

## 4. Configuration

本輪新增 `TRUSTED_PROXY_CIDRS`，並把 signal set 從隱含在 `main()` 內的單一參數抽出為 `monitoredSignals()`，讓 `SIGINT`、`SIGTERM` 與 trusted proxy client IP 行為可由單元測試與靜態檢查固定。

| 項目 | 合約 |
|---|---|
| Local interrupt | `os.Interrupt` / SIGINT |
| Orchestrator shutdown | `syscall.SIGTERM` |
| Trusted proxy | `TRUSTED_PROXY_CIDRS` 空值時不信任 `X-Forwarded-For`；CIDR 命中時才採用第一個 forwarded IP |
| Release gate | `TestMonitoredSignalsContract` 與 `node scripts/check-shutdown-signal-contract.mjs` |

## 6. Troubleshooting

| 症狀 | 可能原因 | 建議處理 |
|---|---|---|
| Kubernetes rolling deploy 後 request 被中斷 | 服務未監聽 `SIGTERM` 或 readiness 未先轉 draining | 檢查 `monitoredSignals()` 與 `/readyz` draining 流程 |
| Ctrl+C 可以關閉但 Docker stop 行為異常 | 只測了 `SIGINT`，未測 `SIGTERM` | 跑 `TestMonitoredSignalsContract` |
| 文件宣稱 graceful shutdown 但 CI 未阻擋退化 | 缺少文件與測試的靜態 gate | 跑 `node scripts/check-shutdown-signal-contract.mjs` |
| 反向代理後限速 key 被偽造 | 直接信任外部 `X-Forwarded-For` | 保持 `TRUSTED_PROXY_CIDRS` 空值或只填內部代理 CIDR |

## 7. Best Practices

- `cmd/` 層應負責 signal、config 與 dependency wiring，不應把 signal set 隱含成不可測的啟動細節。
- graceful shutdown 文件必須明確區分 local Ctrl+C 與 orchestrator / container runtime 的 `SIGTERM`。
- rate limit 若需要讀取 `X-Forwarded-For`，必須先有 trusted proxy CIDR 白名單；外部直連不得覆寫 client IP。
- readiness draining、HTTP shutdown 與 queue drain 必須一起驗證，不能只確認 process 收到訊號。
- signal contract 屬於 deployment behavior，應進 CI gate，而不是只留在 README。

## 8. Risk Notes

本輪修正可在本地透過單元測試與靜態檢查完成，不需要外部服務。正式環境仍需搭配 load balancer readiness policy、Kubernetes termination grace period、Docker stop timeout、worker drain timeout，以及 ingress / gateway 的 forwarded header 清理策略，才能形成完整部署安全邊界。

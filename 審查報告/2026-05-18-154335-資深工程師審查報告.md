## 1. Overview

`v1.0.36` 已完成版本與自動化紀錄標示，但工作樹中仍有一組實際會影響 production API 的 CORS allowlist contract。以資深工程師角度審查，這項缺口值得獨立發布：瀏覽器前端若需要跨域呼叫 API，教材不能用 `Access-Control-Allow-Origin: *` 這類不安全預設，而應把 exact origin allowlist、preflight、blocked origin、設定驗證與 CI gate 一起固定。

## 2. Architecture

| 面向 | 審查結論 |
|---|---|
| API middleware | 需要在 auth/rate-limit 外圍明確處理 CORS preflight 與 actual request header |
| Configuration | `CORS_ALLOWED_ORIGINS` 必須只接受 exact `http` / `https` origin，不接受 path、query、fragment 或 user info |
| Contract tests | 需涵蓋 allowed preflight `204`、actual request header、blocked preflight `403` |
| Documentation | README、API contract、章節、Cheat Sheet、OpenAPI 與整合視覺課程需同步 |
| CI gate | 需新增 `scripts/check-cors-contract.mjs`、Makefile 與 GitHub Actions gate |

## 3. Workflow

```text
CORS_ALLOWED_ORIGINS empty
-> no CORS response header

Origin in allowlist
-> preflight OPTIONS returns 204
-> actual request returns Access-Control-Allow-Origin and Vary: Origin

Origin not in allowlist
-> preflight OPTIONS returns 403
-> actual request does not get CORS allow header
```

## 4. Verification

| 類型 | 指令 |
|---|---|
| Static contract | `node scripts/check-cors-contract.mjs` |
| API focused test | `go test ./internal/api -run 'TestCORSAllowedOriginsContract' -count=1` |
| Config focused test | `go test ./internal/config -run 'TestLoadFromLookup' -count=1` |
| Docs index | `node scripts/fix-docs-index-links.mjs --sync-source && node scripts/fix-docs-index-links.mjs --check` |

## 5. Risk Notes

- CORS 不是認證；API key / Bearer token 仍需保留。
- 不應用 wildcard 解決部署問題，應在前端 domain 穩定後列入 exact origin。
- 若經過 API Gateway 或 ingress，CORS policy 應避免在多層重複注入互相衝突的 header。

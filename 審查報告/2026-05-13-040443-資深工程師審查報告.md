## 審查範圍

- 教材版本：`v1.0.6`
- 教材基準：Go 1.26.3
- 審查角度：專案開發深度、工程廣度、教程內部一致性、可交付專案的 release gate。
- 外部依據：Go 官方 Release History 確認 Go 1.26.3 仍為最新穩定 patch；Go 官方 dependency management 與 govulncheck 文件確認依賴管理與漏洞掃描流程。

## 結論

教程目前已具備從基礎語法到 production API + worker 的完整學習路線，專案開發深度足以支援初中階工程師建立 Go 專案心智模型。前幾輪已補齊 Go 1.26.3、部署矩陣、Docker/CI toolchain 與測試 artifact。

本輪發現的主要缺口不是語法或架構，而是「依賴治理與供應鏈安全」尚未被放進主線 release gate。第 8 章有 `go mod verify`，進階速查表也列出 `go list -m -u all`，但缺少可操作的審核流程：何時升級、如何限制升級範圍、如何判斷漏洞是否阻擋 release、如何在 CI 裡固定工具版本。

## 需要更新的缺口

| 優先級 | 缺口 | 風險 | 建議修正 |
|---|---|---|---|
| P1 | 第 8 章缺少依賴升級審核流程 | 讀者可能把全量升級當成正常維護，造成 breaking change 或安全風險混在同一個 PR | 新增 `go list -m -u all`、指定升級、`go mod tidy`、`go mod verify`、`go test`、`govulncheck` 的流程 |
| P1 | `govulncheck` 未納入主線驗證 | release 只靠測試，無法發現已知可達漏洞 | README、第 9 章、第 11 章加入漏洞掃描 gate |
| P2 | Go 1.24+ tool dependencies 未說明 | CI 與本機可能使用不同版本的工具 | 第 8 章補充 `go get -tool` 與 `go tool govulncheck` |
| P2 | 私有 module 的 checksum 風險說明不足 | `GOPRIVATE` 必要但可能被誤解為可關閉所有校驗 | 第 8 章補上 `GONOSUMCHECK=*` 風險 |
| P3 | 輔助材料未同步依賴治理 | 主章節新增後，康乃爾筆記與速查表仍可能漏掉 release gate | 同步康乃爾筆記、Cheat Sheet、production 專案 README |

## 本輪修正策略

1. 不新增新章節，避免教程結構膨脹。
2. 以第 8 章為主，補足 dependency governance 的流程與決策表。
3. 在 README、第 9 章、第 11 章加入 release / CI gate，讓依賴安全與測試部署形成一條線。
4. 同步更新康乃爾筆記與速查表，降低讀者只看輔助材料時漏掉安全 gate 的風險。

# 第 6 章 併發程式設計（Concurrency）

> 「Don't communicate by sharing memory; share memory by communicating.」 — Rob Pike
>
> 這一章是 Go 的招牌。把這一章吃透，後端寫 code 才能真正進入「Go 模式」。

## 6.1 併發 vs 平行（Concurrency vs Parallelism）

- **Concurrency（併發）**：把問題拆成可獨立進行的多份工作（dealing with lots of things）。
- **Parallelism（平行）**：同時執行多份工作（doing lots of things at once）。

Go 主打**併發**：先寫成可併發結構，能不能真的平行跑由 `GOMAXPROCS` 與作業系統決定。

---

## 6.2 GMP 排程模型（GMP Scheduler）

```
        ┌─── G ───┐  ┌─── G ───┐
G G G G │  G G G  │  │  G G    │   ← G: goroutine（2-8 KB stack，輕量）
        └────┬────┘  └────┬────┘
           [ P ]         [ P ]      ← P: logical processor，數量 = GOMAXPROCS
             │             │
             ▼             ▼
           [ M ]         [ M ]      ← M: OS thread（kernel 排程的單位）
```

- **G（Goroutine）**：使用者層級的「綠色執行緒」，啟動成本極低（~2KB stack，可動態成長）。
- **P（Processor）**：邏輯處理器，掛在 M 上，持有可執行的 G 隊列。
- **M（Machine）**：對應一個 OS thread。

### 關鍵特性
1. **Work stealing**：P 自己 queue 空了會去其他 P 偷 G。
2. **非合作式搶占（Go 1.14+）**：以前 goroutine 不主動 yield 會卡住排程器，現在會被搶占。
3. **網路 I/O 不阻塞 M**：netpoller + epoll/kqueue，I/O 等待時 G 釋出 M。

> 你可以把 GOMAXPROCS 設為 8、開十萬個 goroutine，Go 會幫你排到 8 個 OS thread 上輪流跑。

## 6.3 Goroutine

```go
go func() {
    fmt.Println("hi from goroutine")
}()
```

`go` 關鍵字啟動 goroutine。它**不回傳任何東西**，所以要拿結果只能用 channel。

### 和 OS thread 比

| 項目 | OS thread | Goroutine |
|---|---|---|
| Stack 起始 | 1-8 MB | 2 KB（動態成長） |
| 切換成本 | µs 級 | ns 級 |
| 數量上限 | 數千 | **數百萬** |
| 排程 | OS kernel | Go runtime |

### 啟動規則
- 啟動超快，但**不要無腦開**：每個都要記得「怎麼結束」。
- 沒有 join API；用 `sync.WaitGroup` 或 channel 或 errgroup。

## 6.4 Channel

```go
// Unbuffered（同步 channel）：send 會卡到有人 receive
ch := make(chan int)

// Buffered：buffer 滿才卡 send；空才卡 receive
ch := make(chan int, 10)

ch <- 1     // send
v := <-ch   // receive
v, ok := <-ch  // ok=false 表示 channel 已關閉且無剩餘值

close(ch)    // 由 sender 負責 close
```

### 規則
- **由 sender 負責 close，不要由 receiver close**（否則 panic）。
- **不要對 nil channel 操作**（會永遠阻塞）。
- **不要對已 close 的 channel 再 close 或 send**（panic）。
- **range over channel** 直到 close 才結束：
  ```go
  for v := range ch { ... }
  ```

### 圖解：unbuffered vs buffered

```
unbuffered (size 0)
sender ───X───> receiver    一次只能一手交一手

buffered (size 3)
sender ───> [_,_,_] ───> receiver    sender 可以先丟 3 個再卡
```

## 6.5 `select`：多路複用

```go
select {
case v := <-ch1:
    fmt.Println("from ch1:", v)
case ch2 <- 42:
    fmt.Println("sent to ch2")
case <-time.After(1 * time.Second):
    fmt.Println("timeout")
case <-ctx.Done():
    return ctx.Err()
default:
    fmt.Println("nothing ready")  // 非阻塞 select
}
```

- 多個 case 同時 ready 時**隨機選一個**（防止飢餓）。
- 沒有 case ready 又沒 `default` → 阻塞。
- 加上 `<-ctx.Done()` case 是**標配**，防 goroutine leak。

## 6.6 併發 Patterns（必會 6 種）

### Pattern 1：Worker Pool

固定數量的 worker 處理 jobs：

```go
func WorkerPool(jobs <-chan Job, results chan<- Result, n int) {
    var wg sync.WaitGroup
    for i := 0; i < n; i++ {
        wg.Add(1)
        go func(id int) {
            defer wg.Done()
            for j := range jobs {
                results <- process(j)
            }
        }(i)
    }
    wg.Wait()
    close(results)
}
```

### Pattern 2：Fan-out / Fan-in

把 input 分散到 N 個 worker（fan-out），再合併結果（fan-in）：

```go
// fan-out
func fanOut(in <-chan Job, n int) []<-chan Result {
    outs := make([]<-chan Result, n)
    for i := 0; i < n; i++ {
        ch := make(chan Result)
        outs[i] = ch
        go func() {
            defer close(ch)
            for j := range in { ch <- process(j) }
        }()
    }
    return outs
}

// fan-in
func fanIn(chs ...<-chan Result) <-chan Result {
    out := make(chan Result)
    var wg sync.WaitGroup
    wg.Add(len(chs))
    for _, ch := range chs {
        go func(c <-chan Result) {
            defer wg.Done()
            for v := range c { out <- v }
        }(ch)
    }
    go func() { wg.Wait(); close(out) }()
    return out
}
```

### Pattern 3：Pipeline

每個 stage 是一個 goroutine，用 channel 串起來：

```go
func gen(nums ...int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for _, n := range nums { out <- n }
    }()
    return out
}

func sq(in <-chan int) <-chan int {
    out := make(chan int)
    go func() {
        defer close(out)
        for n := range in { out <- n * n }
    }()
    return out
}

// 使用：gen → sq → sq
for v := range sq(sq(gen(1,2,3,4))) { fmt.Println(v) }
```

### Pattern 4：Semaphore（限制併發數）

用 buffered channel 當 token：

```go
sem := make(chan struct{}, 10)  // 最多 10 併發

for _, url := range urls {
    sem <- struct{}{}  // 取 token
    go func(u string) {
        defer func() { <-sem }()  // 還 token
        fetch(u)
    }(url)
}
```

### Pattern 5：errgroup（並行 + 錯誤收集 + 取消）

```go
import "golang.org/x/sync/errgroup"

g, ctx := errgroup.WithContext(parentCtx)
for _, url := range urls {
    url := url
    g.Go(func() error {
        return fetch(ctx, url)  // 任一錯誤 → ctx 被 cancel
    })
}
if err := g.Wait(); err != nil { return err }
```

### Pattern 6：Done channel（廣播取消）

```go
done := make(chan struct{})
// ...
close(done)  // 廣播：所有 <-done 同時收到

// 多個 goroutine
for i := 0; i < 5; i++ {
    go func() {
        select {
        case <-done:
            return
        case <-doWork():
            // ...
        }
    }()
}
```

> 現代 Go：用 `context.Context` 取代 done channel。

## 6.7 同步原語（Synchronization Primitives）

### `sync.Mutex` / `sync.RWMutex`

```go
var (
    mu sync.RWMutex
    m  = make(map[string]int)
)

func Get(k string) int {
    mu.RLock()
    defer mu.RUnlock()
    return m[k]
}

func Set(k string, v int) {
    mu.Lock()
    defer mu.Unlock()
    m[k] = v
}
```

⭐ **黃金規則**：
- 哪個欄位被 mutex 保護，就把 mutex 放在它附近並寫 comment。
- `Lock` 後立刻 `defer Unlock()`。
- 不要在 mutex 內呼叫可能 block 的程式（HTTP、I/O）。

### `sync.WaitGroup`

```go
var wg sync.WaitGroup
for _, item := range items {
    wg.Add(1)
    go func(it Item) {
        defer wg.Done()
        process(it)
    }(item)
}
wg.Wait()
```

⚠️ `Add` 必須在 `go` 之前；`Done` 一定要 defer。

### `sync.Once`

```go
var once sync.Once
var conn *DB

func GetDB() *DB {
    once.Do(func() {
        conn = mustConnect()
    })
    return conn
}
```

只執行一次，併發安全的單次初始化。

### `sync.Pool`

物件重用池，減 GC 壓力（如 buffer、bytes.Buffer）：

```go
var bufPool = sync.Pool{
    New: func() any { return new(bytes.Buffer) },
}

buf := bufPool.Get().(*bytes.Buffer)
defer func() { buf.Reset(); bufPool.Put(buf) }()
```

⚠️ Pool 的物件**可能隨時被 GC 回收**，不能存「需要持久」的資料。

### `sync/atomic`

原子操作，比 mutex 輕量但只適合單一值：

```go
var counter atomic.Int64

counter.Add(1)
counter.Load()
counter.Store(0)
```

## 6.8 Channel vs Mutex 怎麼選

| 情境 | 用什麼 |
|---|---|
| 傳遞**資料所有權**（生產者 → 消費者） | **Channel** |
| 編排流程（pipeline、fan-out、worker） | **Channel** |
| 保護**共享狀態**（不變的資料結構，多人讀寫） | **Mutex** |
| 計數器 / flag | **atomic** |
| 單次初始化 | **sync.Once** |

> 名言：**「Channels orchestrate; mutexes serialize.」**

## 6.9 Goroutine Leak

最常見的 leak 原因：goroutine 在無條件 `<-ch` 等資料，但 sender 已死/被忘記 close。

### 偵測

```go
// 簡單看數量
fmt.Println(runtime.NumGoroutine())

// 測試用 go.uber.org/goleak
import "go.uber.org/goleak"
func TestMain(m *testing.M) {
    goleak.VerifyTestMain(m)
}
```

### 預防三原則

1. **每個 goroutine 都要有「退出路徑」**：通常是 `<-ctx.Done()` 或 channel close。
2. **用 select + ctx**，別寫純 `<-ch`：
   ```go
   select {
   case v := <-ch: ...
   case <-ctx.Done(): return
   }
   ```
3. **誰開的 goroutine，誰負責清**：在啟動處就規劃結束機制。

## 6.10 race detector

`go test -race` 或 `go run -race`：用編譯器插樁找資料競爭。

```bash
go test -race ./...
```

CI 必開。**找 bug 找一晚不如 race 跑 5 秒。**

## 6.11 完整範例：限流爬蟲

```go
package main

import (
    "context"
    "fmt"
    "net/http"
    "sync"
    "time"

    "golang.org/x/sync/errgroup"
)

func fetch(ctx context.Context, url string) (int, error) {
    req, _ := http.NewRequestWithContext(ctx, "GET", url, nil)
    resp, err := http.DefaultClient.Do(req)
    if err != nil { return 0, err }
    defer resp.Body.Close()
    return resp.StatusCode, nil
}

func main() {
    urls := []string{"https://go.dev", "https://example.com" /* ... */}

    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    g, ctx := errgroup.WithContext(ctx)
    sem := make(chan struct{}, 5)  // 最多 5 併發

    var (
        mu      sync.Mutex
        results = make(map[string]int)
    )

    for _, url := range urls {
        url := url
        g.Go(func() error {
            select {
            case sem <- struct{}{}:
                defer func() { <-sem }()
            case <-ctx.Done():
                return ctx.Err()
            }
            code, err := fetch(ctx, url)
            if err != nil { return err }
            mu.Lock()
            results[url] = code
            mu.Unlock()
            return nil
        })
    }

    if err := g.Wait(); err != nil {
        fmt.Println("error:", err)
    }
    for u, c := range results { fmt.Printf("%s -> %d\n", u, c) }
}
```

整合了：`context` 取消 + errgroup 收錯 + semaphore 限流 + mutex 保護 map。

## 6.12 Idiom 與 Anti-pattern

### ✅ Idiom
- 每個 goroutine 都有 `<-ctx.Done()` 退出路徑
- channel 所有權清楚（誰建立、誰 close）
- worker pool / errgroup 取代「裸 goroutine + WaitGroup」
- 用 race detector 跑 CI
- 共享狀態旁邊寫 mutex 註解

### ❌ Anti-pattern
- 在 receiver close channel
- `go func() { for { ... } }()` 沒有結束條件
- mutex 內呼叫 HTTP / DB
- 用 channel 當「無限大 buffer」（記憶體爆）
- 同一個 channel 的 sender / receiver 散落在多個 package

## 重點回顧

- GMP 模型：goroutine 輕量、work stealing、netpoller。
- Channel 是型別安全的 pipe；select 是多路複用神器。
- 併發 6 大 pattern：worker pool、fan-out/in、pipeline、semaphore、errgroup、done channel。
- `sync` 套件：Mutex、WaitGroup、Once、Pool、atomic。
- 每個 goroutine 都要有退出路徑；race detector 是必備。
- channel 編排、mutex 序列化。

# 第 7 章 大型專案架構

> 寫小程式靠語法，寫大專案靠架構。本章教你把幾百個檔案有序地組織起來。

---

## 7.1 分層架構（Layered Architecture）

Go 後端常用的「四層」結構：

```
┌─────────────────────────────────────┐
│  Transport / Handler 層              │  HTTP / gRPC / CLI
│  - 解析輸入、呼叫 service、回應       │
├─────────────────────────────────────┤
│  Service / Use Case 層               │  商業邏輯
│  - 編排 domain 與 repo               │
├─────────────────────────────────────┤
│  Domain 層                            │  純粹商業實體
│  - struct + method，無 framework 依賴 │
├─────────────────────────────────────┤
│  Repository / Infra 層               │  DB、外部 API
│  - 隱藏儲存細節                       │
└─────────────────────────────────────┘
```

依賴方向**由上往下**：transport 依賴 service，service 依賴 domain 與 repo（透過 interface）。

### 範例骨架

```
internal/
├── domain/
│   └── user.go          // type User struct { ... } + 純方法
├── repository/
│   ├── user.go          // type UserRepo interface + impl
│   └── postgres/
│       └── user.go      // postgres 實作
├── service/
│   └── user.go          // type UserService struct + 商業邏輯
└── transport/
    └── http/
        └── user.go      // HTTP handler，呼叫 service
```

### Domain 層特徵
- 不 import HTTP / gRPC / DB 套件。
- 純粹型別、商業規則、不變條件。
- 容易單元測試。

```go
// internal/domain/user.go
type User struct {
    ID       int
    Email    string
    Verified bool
}

func (u *User) MarkVerified() error {
    if u.Email == "" {
        return errors.New("email required")
    }
    u.Verified = true
    return nil
}
```

### Repository 介面：service 端定義

```go
// internal/service/user.go
type UserRepo interface {
    Find(ctx context.Context, id int) (*domain.User, error)
    Save(ctx context.Context, u *domain.User) error
}

type UserService struct {
    repo UserRepo
}

func New(r UserRepo) *UserService { return &UserService{repo: r} }
```

實作放在 `internal/repository/postgres/`，但**介面在 service**——這就是上一章說的「介面在使用端定義」。

## 7.2 依賴注入（Dependency Injection, DI）

Go 沒有 Spring。最常見三種做法：

### 方式 1：手動 wire（推薦）

```go
// cmd/api/main.go
func main() {
    cfg := config.MustLoad()

    db := mustOpenDB(cfg.DSN)
    defer db.Close()

    userRepo := postgres.NewUserRepo(db)
    userSvc := service.New(userRepo)
    handler := httpx.NewUserHandler(userSvc)

    srv := &http.Server{Addr: cfg.Addr, Handler: handler}
    log.Fatal(srv.ListenAndServe())
}
```

**優點**：清楚、編譯期檢查、易讀、易 trace。
**缺點**：依賴關係變多時會長一點，但通常可接受。

### 方式 2：Google `wire`（程式碼產生器）

宣告 provider，工具產生組裝程式碼：

```go
// wire.go
var Set = wire.NewSet(
    config.Load,
    postgres.NewUserRepo,
    service.NewUserService,
)
```

`go run github.com/google/wire/cmd/wire` 會產生 `wire_gen.go`。

### 方式 3：Uber `fx`（執行期反射 DI 框架）

```go
fx.New(
    fx.Provide(config.Load, postgres.NewUserRepo, service.NewUserService),
    fx.Invoke(startServer),
).Run()
```

**這在 Go 社群偏離主流**——魔法多、報錯藏在 runtime。除非團隊已熟悉，新專案不建議。

### 推薦
**首選手動 wire**；專案夠大才考慮 `wire`；別輕易上 `fx`。

## 7.3 Config 管理（12-Factor Config）

> 「Config in environment.」

### 標準作法：env → struct

```go
// internal/config/config.go
type Config struct {
    Addr    string `env:"ADDR" envDefault:":8080"`
    DSN     string `env:"DATABASE_URL,required"`
    LogJSON bool   `env:"LOG_JSON" envDefault:"false"`
}

func Load() (*Config, error) {
    var c Config
    if err := env.Parse(&c); err != nil { return nil, err }
    return &c, nil
}
```

常用套件：
- `github.com/caarlos0/env/v10`（簡單）
- `github.com/spf13/viper`（多檔多 source，但 over-engineered 的常見抱怨對象）
- `github.com/kelseyhightower/envconfig`（老牌）

### 慣用準則
- **本地 dev 用 `.env`**（套件如 `godotenv` 載入），但**不要 commit**。
- **不要在 code 寫 `os.Getenv` 散落各處**，集中到 `Config` struct。
- **機密**用 secret manager（AWS Secrets Manager、Vault），不要塞 git。
- **環境特化值（dev / staging / prod）只在環境變數中區分**，code 不分支。

## 7.4 Makefile 與 CI/CD

### 標準 Makefile

```makefile
APP := myapp
GO := go
GOLANGCI := golangci-lint
COVERAGE := coverage.out

.PHONY: all build test lint cover run docker clean

all: lint test build

build:
	$(GO) build -ldflags="-s -w" -o bin/$(APP) ./cmd/api

test:
	$(GO) test -race -coverprofile=$(COVERAGE) ./...

cover: test
	$(GO) tool cover -html=$(COVERAGE)

lint:
	$(GOLANGCI) run

run:
	$(GO) run ./cmd/api

docker:
	docker build -t $(APP):latest .

clean:
	rm -rf bin/ $(COVERAGE)
```

### golangci-lint 設定（`.golangci.yml`）

```yaml
linters:
  enable:
    - errcheck
    - govet
    - staticcheck
    - revive
    - gosimple
    - ineffassign
    - unused
    - gofmt
    - goimports
```

### CI 範例（GitHub Actions）

```yaml
name: ci
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: '1.22' }
      - run: go mod download
      - run: golangci-lint run
      - run: go test -race -cover ./...
```

## 7.5 Observability：log、metric、trace

三大支柱：

### Logging（結構化日誌）

```go
import "log/slog"

logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{
    Level: slog.LevelInfo,
}))
slog.SetDefault(logger)

slog.Info("user login", "user_id", 42, "ip", req.RemoteAddr)
```

### Metric（Prometheus）

```go
import "github.com/prometheus/client_golang/prometheus/promhttp"

http.Handle("/metrics", promhttp.Handler())
```

### Trace（OpenTelemetry）

```go
import "go.opentelemetry.io/otel"

tr := otel.Tracer("user-service")
ctx, span := tr.Start(ctx, "GetUser")
defer span.End()
```

### 設計準則
- log / trace / metric 都要帶 **trace ID**。
- 把 ctx 傳到底，handler 一進來就建 trace span。
- error 要 log 一次（通常在最外層 handler）；中間層只 wrap，不重複 log。

## 7.6 健康檢查與優雅關閉（Health Check & Graceful Shutdown）

### Liveness vs Readiness

| 檢查 | 意義 |
|---|---|
| `/livez` | 「我活著」——失敗 → 重啟我 |
| `/readyz` | 「我能服務」——失敗 → 別把流量送來，但別重啟 |

```go
mux.HandleFunc("/livez", func(w http.ResponseWriter, r *http.Request) {
    w.WriteHeader(http.StatusOK)
})

mux.HandleFunc("/readyz", func(w http.ResponseWriter, r *http.Request) {
    if !db.Ping() { w.WriteHeader(503); return }
    w.WriteHeader(http.StatusOK)
})
```

### 優雅關閉

```go
sig := make(chan os.Signal, 1)
signal.Notify(sig, os.Interrupt, syscall.SIGTERM)

go func() {
    if err := srv.ListenAndServe(); err != http.ErrServerClosed {
        log.Fatal(err)
    }
}()

<-sig
ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()
srv.Shutdown(ctx)  // 完成處理中請求、關閉空閒連線
```

K8s 滾動更新時這是必備。

## 7.7 測試策略（Testing Strategy）

### 測試金字塔（Test Pyramid）

```
        /\
       /  \  E2E（少，但價值高）
      /----\
     / Inte- \   Integration / Contract
    /  gration\
   /----------\
  /   Unit     \   單元測試（多，但便宜）
 /--------------\
```

### Domain 層
純單元測試，無 mock。

### Service 層
mock `repo` interface（手寫 mock 或 `gomock`）：

```go
type fakeRepo struct{ users map[int]*domain.User }
func (f *fakeRepo) Find(_ context.Context, id int) (*domain.User, error) {
    u, ok := f.users[id]; if !ok { return nil, ErrNotFound }
    return u, nil
}
```

### Repo 層
**整合測試**：跑真的 DB（用 testcontainers 或 docker-compose）。

> **不要 mock DB**。Mock 出來的 query 跟真實 SQL 行為差異會在生產咬人。

### HTTP 層
`httptest.NewServer` + 真實 handler：

```go
ts := httptest.NewServer(handler)
defer ts.Close()
resp, _ := http.Get(ts.URL + "/users/1")
```

## 7.9 Idiom 與 Anti-pattern

### ✅ Idiom
- `cmd/<name>/main.go` 只做 wire
- domain 不依賴 framework
- repo 介面在 service 端定義
- ctx 傳到底
- 集中 config struct
- 結構化 log + trace ID

### ❌ Anti-pattern
- 圈圈依賴（A 依賴 B、B 依賴 A）
- handler 直接呼叫 DB
- 全域變數存設定（除了 logger 之類）
- mock 整個 DB
- `panic`-driven 控制流
- 一個 service 同時做太多事（god object）

---

## 重點回顧

- 四層架構：transport → service → domain / repo。
- DI 首選手動 wire；別亂上 fx。
- Config 用 env → struct，機密走 secret manager。
- Makefile + golangci-lint + CI 三件套。
- Observability：log / metric / trace 都要 trace ID。
- 優雅關閉：`signal.Notify` + `srv.Shutdown(ctx)`。
- 測試：domain 純測、service mock repo、repo 跑真 DB。

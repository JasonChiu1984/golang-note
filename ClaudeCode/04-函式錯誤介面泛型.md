# 第 4 章 函式、錯誤、介面、泛型

> 函式是 Go 的一等公民，錯誤是值，介面隱式滿足，泛型刻意保守。

---

## 4.1 函式（Functions）

### 基本宣告

```go
func add(a, b int) int {
    return a + b
}

// 多回傳值
func divmod(a, b int) (int, int) {
    return a / b, a % b
}

// 具名回傳值（named return）：可讀性高，但別濫用
func parse(s string) (n int, err error) {
    n, err = strconv.Atoi(s)
    return  // 「裸 return」回傳當前的 n、err
}

// 可變參數（variadic）
func sum(nums ...int) int {
    total := 0
    for _, n := range nums { total += n }
    return total
}
sum(1, 2, 3)
nums := []int{1, 2, 3}
sum(nums...)  // 用 ... 展開 slice
```

### 函式是一等公民

```go
// 函式型別
type Transformer func(int) int

double := func(x int) int { return x * 2 }
var t Transformer = double

// 高階函式
func Map(items []int, f func(int) int) []int {
    out := make([]int, len(items))
    for i, v := range items {
        out[i] = f(v)
    }
    return out
}
```

### Closure（閉包）

```go
func counter() func() int {
    n := 0
    return func() int {
        n++
        return n
    }
}

c := counter()
c()  // 1
c()  // 2
```

⚠️ Go 1.22 之前的 loop variable 陷阱：
```go
// 1.21 及以前
funcs := []func(){}
for i := 0; i < 3; i++ {
    funcs = append(funcs, func() { fmt.Println(i) })
}
for _, f := range funcs { f() }  // 印 3 3 3（共用 i）

// 1.22 起：每次迭代產生新 i，輸出 0 1 2 ✅
```

### `defer`（再強調）
- LIFO 順序執行。
- **參數在 defer 當下計算**，body 在函式結束時執行。
- 在 loop 裡用 defer 開檔案 → 全部累積到函式結束才關 → 易爆。應該改寫一個內層函式。

```go
// ❌ 累積大量 defer
for _, p := range paths {
    f, _ := os.Open(p)
    defer f.Close()  // 全部都到外層函式結束才關
}

// ✅ 改成
for _, p := range paths {
    func() {
        f, _ := os.Open(p)
        defer f.Close()
        // 處理 f
    }()
}
```

## 4.2 錯誤處理（Error Handling）

### 核心觀念：錯誤是值

`error` 是內建 interface：
```go
type error interface {
    Error() string
}
```

任何實作 `Error() string` 的型別都是 error。

### 標準寫法

```go
func loadConfig(path string) (*Config, error) {
    data, err := os.ReadFile(path)
    if err != nil {
        return nil, fmt.Errorf("讀取設定檔 %q 失敗: %w", path, err)
    }
    // ...
}
```

⭐ 三大原則：
1. **錯誤要包裝（wrap）**：用 `%w`，讓上層能 unwrap。
2. **早 return**：`if err != nil { return ... }`，不嵌套。
3. **錯誤訊息全小寫、不加標點**：`"open file"` 不是 `"Open file."`。

### `errors` 套件三件套

```go
// 1. errors.New：建立簡單錯誤
var ErrNotFound = errors.New("not found")

// 2. fmt.Errorf + %w：包裝錯誤
return fmt.Errorf("user %d: %w", id, ErrNotFound)

// 3. errors.Is / errors.As：辨識錯誤
if errors.Is(err, ErrNotFound) {
    // 知道根因是 ErrNotFound，即使被包裝多層
}

var pathErr *os.PathError
if errors.As(err, &pathErr) {
    fmt.Println(pathErr.Path)
}
```

### Sentinel Error vs Error Type vs Behavior

| 模式 | 例子 | 何時用 |
|---|---|---|
| Sentinel | `var ErrNotFound = errors.New(...)` | 簡單分類 |
| Type | `type ValidationErr struct { Field, Msg string }` | 需要附帶結構化資訊 |
| Behavior | `interface { Temporary() bool }` | 標誌錯誤特性（如 net.Error） |

### 自訂錯誤型別

```go
type ValidationError struct {
    Field   string
    Message string
}

func (e *ValidationError) Error() string {
    return fmt.Sprintf("%s: %s", e.Field, e.Message)
}

// 使用端
err := validate(input)
var ve *ValidationError
if errors.As(err, &ve) {
    log.Printf("invalid %s: %s", ve.Field, ve.Message)
}
```

### `panic` 不是錯誤替代品

| 場景 | 用 |
|---|---|
| 預期會發生（檔案不存在、連線失敗） | `error` |
| 程式設計者 bug（不應發生） | `panic` |
| 不可恢復狀態（記憶體耗盡） | `panic` |

> Library 不 `panic`；HTTP server 用 middleware `recover` 防止單一 handler 崩潰整個 server。

```go
defer func() {
    if r := recover(); r != nil {
        log.Printf("panic recovered: %v", r)
    }
}()
```

## 4.3 Interface（介面）

### 隱式滿足（Structural Typing）

```go
type Stringer interface {
    String() string
}

type User struct{ Name string }
func (u User) String() string { return u.Name }

// User 自動滿足 Stringer，不需要寫 implements
var s Stringer = User{Name: "Amy"}
```

### Go 介面設計三原則

#### (1) 越小越好
標準庫經典：
```go
type Reader interface {
    Read(p []byte) (n int, err error)
}
type Writer interface {
    Write(p []byte) (n int, err error)
}
type Closer interface {
    Close() error
}
```

組合：
```go
type ReadCloser interface {
    Reader
    Closer
}
```

> 「The bigger the interface, the weaker the abstraction.」 — Rob Pike

#### (2) 在使用端定義（Consumer-Side）

```go
// ❌ 在被實作端定義
package storage
type Storage interface {
    Save(...) error
    Load(...) ([]byte, error)
    Delete(...) error
    List(...) ([]string, error)
    // ... 大雜燴
}

// ✅ 在使用端定義「我需要什麼」
package report
type Saver interface {
    Save(name string, data []byte) error
}
func Generate(s Saver) { ... }
```

這樣 `report` 不依賴 `storage` 的所有方法，測試時也好 mock。

#### (3) 描述「行為」，不描述「資料」
- ✅ `type Sortable interface { Less(i, j int) bool }`
- ❌ `type UserData interface { GetName() string; GetAge() int }`（這就是 Java getter，純取資料用 struct 即可）

### 編譯期 Interface 檢查

```go
var _ http.Handler = (*MyHandler)(nil)
```

把 `(*MyHandler)(nil)` 賦值給 `http.Handler` 變數，**只在編譯期檢查**型別，不會執行。漏實作方法時編譯就掛。

### Empty Interface：`any`

`any` 是 `interface{}` 的別名（Go 1.18+），可裝**任何值**。

```go
func PrintAny(v any) {
    fmt.Println(v)
}
```

⚠️ `any` 是放棄型別安全；現代 Go 應優先用**泛型**。

### Type Assertion（型別斷言）

```go
var x any = "hello"
s := x.(string)         // 直接斷言：型別不對會 panic
s, ok := x.(string)     // 安全斷言：ok=false 不 panic
```

### Type Switch

```go
switch v := x.(type) {
case int:    fmt.Println("int", v)
case string: fmt.Println("string", v)
case nil:    fmt.Println("nil")
default:     fmt.Printf("unknown %T\n", v)
}
```

### nil interface 的陷阱（必看）

```go
func bad() error {
    var e *MyError
    if /* nothing wrong */ {
        return e  // ⚠️ e 是 *MyError(nil)，但回傳後 err != nil 會是 true！
    }
    return nil
}

err := bad()
if err != nil {  // 這會進來！
    // ...
}
```

原因：interface 是 `(type, value)` 兩格資訊。
`return e` 時 type 是 `*MyError`、value 是 nil → interface 不是 nil。

⭐ **解法**：函式回傳 `error` 時，要 nil 就明確 `return nil`，不要回傳 typed nil pointer。

## 4.4 Generics（泛型，Go 1.18+）

### 基本語法

```go
func Map[T, U any](items []T, f func(T) U) []U {
    out := make([]U, len(items))
    for i, v := range items {
        out[i] = f(v)
    }
    return out
}

doubled := Map([]int{1, 2, 3}, func(x int) int { return x * 2 })
names := Map(users, func(u User) string { return u.Name })
```

### Type Parameter 與 Constraint

`[T any]` 中的 `any` 是 constraint（約束）。內建約束：
- `any`：任何型別
- `comparable`：可用 `==` `!=` 比較的型別

#### 自訂 constraint
```go
type Number interface {
    ~int | ~int32 | ~int64 | ~float32 | ~float64
}

func Sum[T Number](nums []T) T {
    var s T
    for _, n := range nums { s += n }
    return s
}
```

`~int` 中的 `~` 表示「底層型別是 int 的所有型別」（包含 `type MyInt int`）。

### 何時用泛型？

✅ **用泛型**：
- 容器型資料結構（Stack、Set、LinkedList）
- 通用演算法（Map、Filter、Reduce）
- 想避免 `any` + type assertion

❌ **不用泛型**：
- 只有一兩個型別會用 → 直接寫多個版本（Go 慣例）
- interface 已能優雅表達 → interface 優先（如 `io.Reader`）
- 為了「萬一以後要用」 → YAGNI

> Rob Pike: 「Don't design with interfaces, discover them.」泛型同理：先寫具體版本，重複到第三次再抽。

### `slices`、`maps`（Go 1.21+）

標準庫已用泛型重寫常用工具：

```go
import "slices"
slices.Sort(s)
slices.Contains(s, x)
slices.Index(s, x)
slices.Reverse(s)
slices.Clone(s)

import "maps"
maps.Keys(m)
maps.Values(m)
maps.Clone(m)
```

## 4.5 函式設計綜合範例

把本章所有觀念綜合：

```go
package userrepo

import (
    "context"
    "errors"
    "fmt"
)

var ErrNotFound = errors.New("user not found")

type Finder[T any] interface {
    Find(ctx context.Context, id int) (T, error)
}

type User struct {
    ID   int
    Name string
}

type Repo struct { /* ... */ }

func (r *Repo) Find(ctx context.Context, id int) (*User, error) {
    if id <= 0 {
        return nil, fmt.Errorf("invalid id %d: %w", id, ErrNotFound)
    }
    // ... 查詢邏輯 ...
    return &User{ID: id, Name: "Amy"}, nil
}

// 編譯期確認 Repo 滿足 Finder
var _ Finder[*User] = (*Repo)(nil)
```

## 4.6 Idiom 與 Anti-pattern

### ✅ Idiom
- 多回傳值最後一個是 `error`
- 錯誤訊息「不大寫、不加標點」、含 context 但不重複「failed to」
- interface 寫在使用端、越小越好
- 函式參數用具體型別、回傳用 interface（postel principle）
- Generics 只用於通用資料結構與演算法

### ❌ Anti-pattern
- 回傳 `error` 然後 `if err != nil { panic(err) }`
- 自訂 error type 卻沒寫 `Error()` 方法
- 巨大 interface（10+ method）丟到 service 層
- 把所有東西都泛型化
- `interface{}` (`any`) 滿天飛

---

## 重點回顧

- 函式可多回傳值；`defer` 用對能少寫很多錯誤處理。
- 錯誤是值：`fmt.Errorf("...%w", err)` 包裝、`errors.Is/As` 辨識。
- Interface 隱式滿足、越小越好、寫在使用端。
- nil interface 陷阱：別回傳 typed nil。
- Generics 慎用：先寫具體、再抽通用。

# 第 8 章 版本管理（Modules & Semantic Versioning）

> Go 1.11 後正式進入 module 時代。本章把 `go.mod` / `go.sum` / SemVer / 私有 module 一次講透。

---

## 8.1 Semantic Versioning（SemVer）

版號格式：`MAJOR.MINOR.PATCH`

| 段 | 變動條件 |
|---|---|
| MAJOR | **不相容**的 API 變更 |
| MINOR | 向後相容的**新功能** |
| PATCH | 向後相容的**修 bug** |

例：
- `v1.4.2` → 新增功能 → `v1.5.0`
- `v1.5.0` → 修 bug → `v1.5.1`
- `v1.5.1` → 移除 API → `v2.0.0`

### v0.x.x：開發期，破壞性變更不算「違反 SemVer」

在 `v1.0.0` 釋出前，作者保留隨時改動的權利。

### Pre-release / Build metadata

- `v1.5.0-beta.1`：pre-release
- `v1.5.0+build.20260510`：build metadata（Go 不太用）

## 8.2 `go.mod` 完整解剖

```
module github.com/you/svc

go 1.22

require (
    github.com/gin-gonic/gin v1.9.1
    github.com/jackc/pgx/v5 v5.5.0
    golang.org/x/sync v0.5.0
)

require (
    // indirect 依賴（你的依賴的依賴）
    github.com/bytedance/sonic v1.10.2 // indirect
)

replace github.com/foo/bar => ../bar     // 指向本地或 fork
exclude github.com/baz v1.0.0            // 排除壞掉的版本
retract v1.0.1                            // 自己撤回有問題的版本
```

### 五大指令動詞

| 動詞 | 用途 |
|---|---|
| `module` | 本 module 的路徑（建議用 repo URL） |
| `go` | 使用的 Go 版本 |
| `require` | 直接 / 間接依賴 |
| `replace` | 把某依賴換成本地或其他 fork（debug 神器） |
| `exclude` | 不允許某版本 |
| `retract` | 自己撤回（讓使用者 `go get` 看不到該版本） |

## 8.3 `go.sum`：依賴的指紋簿

每個依賴記兩行（module zip + go.mod hash），確保 build 可重現。

```
github.com/gin-gonic/gin v1.9.1 h1:4idEAncQnU5cB7BeOkPtxjfCSye0AAm1R0RVIqJ+Jmg=
github.com/gin-gonic/gin v1.9.1/go.mod h1:hPrL7YrpYKXt5YId3A/Tnip5kqbEAA+m9hKtMlbU0J4=
```

⭐ **一定要 commit `go.sum`**：CI 與隊友 build 才會驗證一致。

驗證會用 sum DB（`GOSUMDB=sum.golang.org`），確保「全世界看到的版本內容一致」。

## 8.4 常用 module 指令

```bash
# 初始化
go mod init github.com/you/svc

# 加入新依賴
go get github.com/gin-gonic/gin@v1.9.1
go get github.com/foo/bar@latest
go get github.com/foo/bar@master    # 用 commit / branch
go get github.com/foo/bar@a1b2c3d   # 用 commit hash

# 同步：刪沒用的、補缺的
go mod tidy

# 升級：所有依賴升 minor / patch
go get -u ./...

# 升級：包含 indirect
go get -u all

# 查看依賴樹
go mod graph

# 為什麼有這個依賴？
go mod why github.com/some/dep

# 把依賴複製到本地 vendor/（離線 build 用）
go mod vendor
```

## 8.5 Major Version v2+：路徑要加 `/v2`

Go 的 module 系統規定：**v2 以上必須在 import 路徑加版本字尾**。

```go
// v1.x.x：原本路徑
import "github.com/foo/bar"

// v2.x.x：必須加 /v2
import "github.com/foo/bar/v2"
```

對應 `go.mod`：
```
module github.com/foo/bar/v2

go 1.22
```

> 這是為了讓**同一份程式同時能用 v1 與 v2**（避免 dependency hell）。

### 三種 v2+ 釋出方式

1. **建立 `v2/` 子目錄**，獨立 `go.mod`（同 repo 多 module）
2. **`v2` 分支**，獨立 `go.mod`
3. **`gopkg.in` 風格**（少見）

最常見是方式 2：在 main 分支發 v1.x、在 v2 分支發 v2.x。

## 8.6 Private Module（私有套件）

公司內部套件不在公開 proxy 上時：

```bash
# 1. 設定 GOPRIVATE：跳過 proxy 與 sum 檢查
go env -w GOPRIVATE='*.corp.com,github.com/myorg/*'

# 2. 設定 git 認證（HTTPS）
# ~/.netrc:
# machine github.com login YOU password TOKEN

# 3. 或改用 SSH
git config --global url."git@github.com:".insteadOf "https://github.com/"
```

相關環境變數：
- `GOPRIVATE`：哪些路徑視為私有（不走 proxy、不查 sum）。
- `GONOSUMCHECK`：跳過 sum DB 校驗（不建議全開）。
- `GONOPROXY`：哪些路徑跳過 proxy（一般用 `GOPRIVATE` 一起）。
- `GOPROXY=https://proxy.corp.com,direct`：用公司內部 proxy。

## 8.7 多 Module Repo（Monorepo）

一個 repo 可以放多個 `go.mod`：

```
my-repo/
├── api/
│   ├── go.mod        // module github.com/you/repo/api
│   └── ...
└── worker/
    ├── go.mod        // module github.com/you/repo/worker
    └── ...
```

開發時用 `go.work`（Go 1.18+）做 workspace：

```bash
go work init ./api ./worker
```

`go.work`：
```
go 1.22

use (
    ./api
    ./worker
)
```

⚠️ **`go.work` 不要 commit**（除非整個團隊有共識）。它是個人開發用的指向工具。

## 8.8 升級依賴的策略

### 安全的升級流程

```bash
# 1. 看有什麼能升
go list -u -m all

# 2. 升 patch
go get -u=patch ./...

# 3. 跑測試 + race + lint
go test -race ./...
golangci-lint run

# 4. 升 minor（謹慎）
go get -u ./...
go test -race ./...

# 5. 升 major（讀 release notes）
go get github.com/foo/bar/v2
# 修 import path 等等
```

### 工具
- `dependabot` / `renovate`：自動發 PR
- `govulncheck`：掃 CVE 漏洞
  ```bash
  go install golang.org/x/vuln/cmd/govulncheck@latest
  govulncheck ./...
  ```

## 8.9 `replace`：本地 debug 與 fork

### 場景 1：debug 上游 bug

```
replace github.com/foo/bar => /Users/me/code/bar
```

改完上游程式 → 在自家 module 立刻看到效果。修好後 PR 上去、移除 `replace`。

### 場景 2：暫時用 fork

```
replace github.com/foo/bar => github.com/me/bar v1.0.0-mypatch.1
```

> ⚠️ `replace` 屬於「臨時手段」。**長期使用會讓 `go.sum` 校驗繞過**，CI/CD 上線前要解掉。

## 8.10 Idiom 與 Anti-pattern

### ✅ Idiom
- module path 用 repo 真實 URL
- commit `go.mod` + `go.sum`
- 釋出版本打 git tag（`v1.2.3`）
- v2+ 在路徑加 `/v2`
- 跑 `govulncheck` 進 CI

### ❌ Anti-pattern
- 不 commit `go.sum`
- `replace` 永遠不解掉
- 在 main 分支同時混 v1 與 v2 程式
- `go get -u` 一口氣全升、再丟給隊友驚喜
- 把私有 module 放公開 proxy

---

## 重點回顧

- SemVer：MAJOR 不相容、MINOR 加功能、PATCH 修 bug。
- `go.mod`：require、replace、exclude、retract。
- `go.sum`：build 可重現的指紋簿，必 commit。
- 常用：`go mod init/tidy/graph`、`go get pkg@ver`。
- v2+ 必須路徑加 `/v2`。
- 私有 module：`GOPRIVATE` + git 認證。
- 升級流程：patch → 測 → minor → 測 → major（讀 release notes）。

# 第 9 章 打包與部署（Build & Deployment）

> Go 最爽的部分：一個靜態執行檔，到哪都能跑。

---

## 9.1 基本編譯

```bash
# 編譯當前目錄的 main package
go build

# 指定輸出檔名與目錄
go build -o bin/app ./cmd/api

# 編譯整個 module
go build ./...

# 編譯後安裝到 $GOBIN
go install ./cmd/api
```

---

## 9.2 交叉編譯（Cross Compile）

設 `GOOS` + `GOARCH`：

```bash
# Linux x86_64
GOOS=linux GOARCH=amd64 go build -o bin/app-linux ./cmd/api

# Linux ARM64（樹莓派 / AWS Graviton）
GOOS=linux GOARCH=arm64 go build -o bin/app-arm64 ./cmd/api

# macOS Apple Silicon
GOOS=darwin GOARCH=arm64 go build -o bin/app-darwin-arm64 ./cmd/api

# Windows
GOOS=windows GOARCH=amd64 go build -o bin/app.exe ./cmd/api
```

### 列出所有可能組合
```bash
go tool dist list
```

## 9.3 `CGO_ENABLED=0`：純靜態執行檔

預設 `CGO_ENABLED=1`，意味某些套件（如 `net`、`os/user`）**會連 libc**，導致：
- 跨平台編譯失敗（缺 cross compiler）
- 在 Alpine（musl libc）跑 glibc 編譯的 binary 會掛
- Docker scratch image 無法用

**解法**：

```bash
CGO_ENABLED=0 go build -o app ./cmd/api
```

關掉 cgo 後**生出來是純靜態執行檔**，可以放任何 Linux 上跑、可以塞進 `FROM scratch`。

⚠️ 副作用：
- DNS 解析改用 Go 內建（多數情況沒差）
- 用到 cgo 的套件（少數）會編譯錯誤

## 9.4 Build Flags：注入版本、瘦身

### `-ldflags` 注入變數

```go
// main.go
package main

var (
    version = "dev"
    commit  = "none"
    date    = "unknown"
)

func main() {
    fmt.Printf("v=%s commit=%s built=%s\n", version, commit, date)
}
```

```bash
go build -ldflags "-X main.version=v1.2.3 -X main.commit=$(git rev-parse --short HEAD) -X main.date=$(date -Iseconds)"
```

### `-s -w` 瘦身

```bash
go build -ldflags "-s -w" -o app .
```

| Flag | 移除 |
|---|---|
| `-s` | symbol table（排版用，無實際影響） |
| `-w` | DWARF debug info（`pprof` debug 受影響） |

⚠️ 加了 `-w` 後 production debug 變難，若你會 attach delve / pprof 不要加。

### `-trimpath`：去掉本機路徑

```bash
go build -trimpath -ldflags "-s -w" .
```

讓 stack trace 不洩漏 build 機器的絕對路徑（安全 + reproducible build）。

## 9.5 `//go:embed`：嵌入靜態資源

```go
package main

import (
    "embed"
    "net/http"
)

//go:embed static/*
var static embed.FS

func main() {
    http.Handle("/", http.FileServer(http.FS(static)))
    http.ListenAndServe(":8080", nil)
}
```

- 編譯時把檔案打進 binary，部署只要一個檔。
- 適合：HTML / JS / SQL migrations / 預設設定檔。

```go
//go:embed config.yaml
var defaultConfig []byte

//go:embed templates/*.html
var tmplFS embed.FS
```

## 9.6 Build Tags：條件編譯

### 用法 1：依平台

```go
//go:build linux

package myapp

func init() { /* linux-only init */ }
```

或檔名後綴：`foo_linux.go`、`foo_windows.go`、`foo_arm64.go`。

### 用法 2：自訂 tag（常見：integration test）

```go
//go:build integration

package mypkg
// 整合測試
```

```bash
go test -tags integration ./...
```

### 規則
- 注釋必須在檔案最上方，**緊接 package 之前**，且後面要有空行。
- 多條件用 `&&`、`||`、`!`：
  ```go
  //go:build linux && (amd64 || arm64)
  ```

## 9.7 Docker Multi-Stage Build

把編譯與部署分兩階段，最終映像極小：

```dockerfile
# ---- builder ----
FROM golang:1.22-alpine AS builder

WORKDIR /src

# 先複製 mod 檔，利用 layer cache
COPY go.mod go.sum ./
RUN go mod download

# 複製其他原始碼
COPY . .

ARG VERSION=dev
ARG COMMIT=none
ARG DATE=unknown

RUN CGO_ENABLED=0 GOOS=linux go build \
    -ldflags="-s -w \
        -X main.version=${VERSION} \
        -X main.commit=${COMMIT} \
        -X main.date=${DATE}" \
    -trimpath \
    -o /app ./cmd/api

# ---- runtime ----
FROM gcr.io/distroless/static-debian12:nonroot

COPY --from=builder /app /app
EXPOSE 8080
USER nonroot:nonroot
ENTRYPOINT ["/app"]
```

### 為什麼這樣寫？

1. **`golang:1.22-alpine` builder**：有 toolchain。
2. **`gcr.io/distroless/static`**：只有 ca-certificates、tzdata、執行檔需要的最小環境（沒有 shell、沒有 package manager）。映像 ~2 MB + 你的 binary。
3. **`scratch` 替代方案**：更小但連 ca-certs 都沒有，HTTPS 會掛。實務首選 distroless。
4. **`nonroot` user**：安全強化。

### 建構與推送

```bash
docker build \
    --build-arg VERSION=v1.2.3 \
    --build-arg COMMIT=$(git rev-parse --short HEAD) \
    --build-arg DATE=$(date -u +%Y-%m-%dT%H:%M:%SZ) \
    -t myapp:v1.2.3 .

docker push myapp:v1.2.3
```

## 9.8 Reproducible Build（可重現建構）

要讓「每次 build 出來的 binary 完全相同」（safety / supply chain）：

```bash
CGO_ENABLED=0 \
GOFLAGS='-trimpath -buildvcs=false' \
go build -ldflags="-s -w -buildid=" -o app .
```

加上：
- `-trimpath`：去本機路徑
- `-buildvcs=false`：不嵌入 git info
- `-buildid=`：清空隨機 build ID

## 9.9 部署到 Kubernetes（範本）

### Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: myapp
spec:
  replicas: 3
  selector:
    matchLabels: { app: myapp }
  template:
    metadata:
      labels: { app: myapp }
    spec:
      containers:
        - name: myapp
          image: myapp:v1.2.3
          ports: [{ containerPort: 8080 }]
          env:
            - name: ADDR
              value: ":8080"
            - name: DATABASE_URL
              valueFrom:
                secretKeyRef: { name: db, key: url }
          resources:
            requests: { cpu: "100m", memory: "64Mi" }
            limits:   { cpu: "500m", memory: "256Mi" }
          livenessProbe:
            httpGet: { path: /livez, port: 8080 }
            initialDelaySeconds: 5
          readinessProbe:
            httpGet: { path: /readyz, port: 8080 }
            initialDelaySeconds: 2
          # 給優雅關閉留時間
          terminationGracePeriodSeconds: 30
```

關鍵搭配：
- 程式收到 `SIGTERM` → `srv.Shutdown(ctx)`
- K8s 預設給 30 秒 graceful 期間 → 程式 `Shutdown` ctx timeout 設 < 30s

## 9.10 GoReleaser：一鍵發版

`goreleaser` 是 Go 圈最流行的 release 工具：自動編譯多平台、產生 changelog、推 GitHub Release / Docker / Homebrew tap。

`.goreleaser.yaml`：
```yaml
project_name: myapp
builds:
  - main: ./cmd/api
    binary: myapp
    env: [CGO_ENABLED=0]
    goos: [linux, darwin, windows]
    goarch: [amd64, arm64]
    ldflags:
      - -s -w
      - -X main.version={{.Version}}
      - -X main.commit={{.Commit}}
      - -X main.date={{.Date}}

archives:
  - format: tar.gz
    format_overrides:
      - goos: windows
        format: zip

release:
  draft: false
  prerelease: auto
```

```bash
goreleaser release --clean   # 從最新 tag release
goreleaser build --snapshot  # 不發布只 build
```

## 9.11 效能與監控

### Profiling（pprof）

```go
import _ "net/http/pprof"

go http.ListenAndServe(":6060", nil)
```

`localhost:6060/debug/pprof/`：CPU / memory / goroutine / mutex / block 等剖析。

### `runtime/pprof` + 檔案
```go
f, _ := os.Create("cpu.prof")
pprof.StartCPUProfile(f)
defer pprof.StopCPUProfile()
```

### `go tool pprof` 分析
```bash
go tool pprof http://localhost:6060/debug/pprof/heap
(pprof) top
(pprof) web
```

### Profile-Guided Optimization（Go 1.21+）

收集 production profile → build 時帶進去 → 編譯器做更聰明的 inline。

```bash
go build -pgo=cpu.pprof -o app .
```

## 9.12 安全強化（Production Hardening）

| 項目 | 做法 |
|---|---|
| 不以 root 執行 | Dockerfile `USER nonroot` |
| 不 embed 機密 | 用 K8s Secret / Vault |
| 不洩漏路徑 | `-trimpath` |
| 防 panic 整個倒 | HTTP middleware `recover` |
| 漏洞掃描 | `govulncheck`、Trivy / Grype 掃 image |
| 訊號處理 | 接 `SIGTERM` + graceful shutdown |
| Resource limit | K8s requests/limits + Go GOMEMLIMIT (1.19+) |
| 限速 / 熔斷 | `golang.org/x/time/rate`、`gobreaker` |

## 9.13 Idiom 與 Anti-pattern

### ✅ Idiom
- `CGO_ENABLED=0` + multi-stage Docker
- `-ldflags` 注入版本資訊
- `embed` 靜態資源
- 接 SIGTERM + `srv.Shutdown(ctx)`
- `govulncheck` 進 CI

### ❌ Anti-pattern
- 把 `go.sum` 排除在 image 外
- 用 `golang:1.22` 當 runtime image（500 MB+）
- 容器內 root 權限
- 把機密寫在 Dockerfile / git
- 沒有健康檢查 endpoint
- 沒有 graceful shutdown

---

## 重點回顧

- 一個指令編譯出單一執行檔；交叉編譯設 `GOOS` / `GOARCH`。
- `CGO_ENABLED=0` 產純靜態檔；可塞進 distroless / scratch。
- `-ldflags` 注入版本、`-s -w -trimpath` 瘦身與安全。
- `embed` 把靜態檔打進 binary。
- Docker multi-stage：alpine builder + distroless runtime。
- K8s：liveness / readiness + graceful shutdown。
- 觀測：`pprof`、`govulncheck`、結構化 log。

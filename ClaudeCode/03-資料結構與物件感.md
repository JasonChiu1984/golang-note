# 第 3 章 資料結構與物件感（OOP-feel）

> Go 沒有 class，但能做出比 class 更乾淨的「物件感」。本章是讓 OOP 工程師「轉換腦」的關鍵。

---

## 3.1 Array（固定大小）

```go
var a [5]int          // [0 0 0 0 0]
b := [3]string{"a", "b", "c"}
c := [...]int{1, 2, 3}  // 編譯器數元素數
```

特性：
- **長度是型別的一部分**：`[3]int` 與 `[5]int` 是不同型別。
- 賦值是**整份複製**（傳進函式也複製，可能很慢）。
- 實務上很少直接用 array，**都用 slice**。

---

## 3.2 Slice（動態陣列）

```go
s := []int{1, 2, 3}
s = append(s, 4)               // [1 2 3 4]
s2 := make([]int, 0, 10)        // len=0, cap=10（預先配置容量）
copy(dst, src)                  // 複製元素
sub := s[1:3]                   // [2 3]，與 s 共用底層 array
```

### Slice 的「三件組」

```
slice header (24 bytes)
┌──────────┬──────┬──────┐
│   ptr    │ len  │ cap  │
└──────────┴──────┴──────┘
       │
       ▼
   [_, _, _, _, _, _, _, _]   ← 底層 array
       └─ len ─┘
       └────── cap ──────┘
```

- `len(s)`：當前長度
- `cap(s)`：底層 array 從 ptr 起算的容量
- `append` 在 `len < cap` 時直接寫入；`len == cap` 時**新建底層 array**（通常成長為 2 倍）

### ⚠️ 共享底層的陷阱

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]      // [2 3]
b[0] = 99
fmt.Println(a)   // [1 99 3 4 5] —— a 被改了！
```

> **解法**：要獨立副本就用 `slices.Clone(a)`（Go 1.21+）或 `append([]int{}, a...)`。

### `append` 可能新建 array

```go
b := a[1:3]        // 與 a 共用
b = append(b, 99)  // 若 b 還有 cap，仍共用；若沒有，新建獨立 array
```

⭐ Idiom：**永遠把 `append` 的結果接回來**。
```go
s = append(s, x)   // ✅ 一定要這樣寫
```

### `make` 與 `new`

```go
s := make([]int, 0, 10)    // make 用於 slice/map/channel
p := new(int)              // new(T) 回傳 *T，零值
*p = 5
```

口訣：**make 給「需要初始化內部結構」的型別、new 給「想要零值指標」的需求**。

## 3.3 Map（雜湊表）

```go
m := map[string]int{"a": 1, "b": 2}
v, ok := m["a"]         // ok=true if exists
delete(m, "a")
for k, v := range m { } // ⚠️ 順序每次不同
```

### 注意事項
- 零值 map（`var m map[string]int`）讀 OK 但**寫 panic**。
- 用 `make(map[K]V)` 或 `map[K]V{}` 才能寫。
- map 不是 thread-safe。併發讀寫直接 crash（**fatal error**，不是 panic 可 recover）。

### 併發安全選項
```go
// 方案 1：sync.Mutex 保護
var (
    mu sync.RWMutex
    m  = make(map[string]int)
)
mu.Lock(); m["k"] = 1; mu.Unlock()

// 方案 2：sync.Map（適合「讀多寫少 + key 變動」場景）
var sm sync.Map
sm.Store("k", 1)
v, ok := sm.Load("k")
```

> sync.Map 不是萬靈丹，**很多場景反而比 mutex+map 慢**；不要 default 用它。

### 順序輸出
要按 key 排序輸出：
```go
keys := make([]string, 0, len(m))
for k := range m { keys = append(keys, k) }
sort.Strings(keys)
for _, k := range keys { fmt.Println(k, m[k]) }
```

## 3.4 Struct（結構）

```go
type User struct {
    ID   int    `json:"id" db:"id"`
    Name string `json:"name,omitempty"`
    Age  int    `json:"age"`
}

// 建立實例（一律具名欄位，避免欄位增刪後位置錯誤）
u := User{ID: 1, Name: "Amy", Age: 30}
u2 := &User{ID: 2, Name: "Bob"}  // 直接拿指標
```

### Struct Tag

寫在欄位後的反引號字串，是 reflection 看的「中繼資料」（metadata）。常見：

| Tag | 用途 |
|---|---|
| `json:"name"` | encoding/json 序列化欄位名 |
| `json:"name,omitempty"` | 零值省略 |
| `json:"-"` | 忽略此欄位 |
| `db:"name"` | sqlx、gorm 欄位映射 |
| `validate:"required,min=3"` | go-playground/validator |
| `yaml:"name"` | gopkg.in/yaml.v3 |
| `xml:"name,attr"` | encoding/xml |

### Constructor 慣例

Go 沒有 constructor 語法，慣例寫一個 `NewXxx` 函式：

```go
func NewUser(name string) *User {
    return &User{
        ID:   nextID(),
        Name: name,
        Age:  0,
    }
}
```

> 為什麼回傳 `*User` 不是 `User`？
> 因為**只要有可能修改、或有方法是 pointer receiver**，就用指標；少了「值/指標 method set 不一致」的麻煩。

### 匿名 struct（Anonymous Struct）

table-driven test 與一次性資料常用：

```go
tests := []struct {
    name string
    in   int
    want string
}{
    {"zero", 0, "zero"},
    {"pos",  1, "pos"},
}
for _, tc := range tests {
    t.Run(tc.name, func(t *testing.T) { ... })
}
```

## 3.5 Pointer（指標）

```go
x := 10
p := &x       // *int
fmt.Println(*p)  // 10
*p = 20
fmt.Println(x)   // 20
```

### 何時用指標？

1. **修改原物件**：`func (u *User) Rename(s string)`
2. **避免大 struct 複製**：`func process(req *BigRequest)`
3. **可選值（optional）**：`var deletedAt *time.Time`（nil 代表沒刪除）
4. **共享狀態**：多個 goroutine 對同一份資料

### `nil` 安全性
```go
var u *User
u.Name             // panic: nil pointer dereference
if u != nil { ... }
```

> Idiom：函式接受指標時，**第一行就檢查 nil**（如果你不想用零值處理）。

### `new` 與 `&T{}`
```go
p := new(User)      // *User，零值
p := &User{}        // *User，零值（更常見）
p := &User{ID: 1}   // 同時設值
```

## 3.6 Method（方法）

Go 的 method 就是「綁在型別上的函式」：

```go
type User struct {
    Name string
}

// Value receiver：u 是副本
func (u User) Display() string {
    return u.Name
}

// Pointer receiver：u 是原物件指標
func (u *User) Rename(n string) {
    u.Name = n  // 改的是原物件
}
```

### Value receiver vs Pointer receiver

| 情境 | 選什麼 |
|---|---|
| 需要修改 receiver | **指標** |
| receiver 很大（複製成本高） | **指標** |
| receiver 是 map / slice / chan / func / interface | 通常**值**（它們本身是 header） |
| 想保證「不可變」 | **值**（呼叫者拿到的是副本） |

⭐ **黃金規則**：**同一型別的所有方法統一**——要嘛全 value、要嘛全 pointer。混用會讓 method set 規則變得很難理解。

### Method Set 規則

「型別 T 的 method set」決定哪些 interface 能滿足：

| Receiver 型別 | T 值有的 method | *T 值有的 method |
|---|---|---|
| `func (t T) M()` | ✅ 有 | ✅ 有 |
| `func (t *T) M()` | ❌ 沒有 | ✅ 有 |

```go
type Animal interface { Speak() }

type Dog struct{}
func (d *Dog) Speak() {}  // pointer receiver

var a Animal
a = Dog{}      // ❌ 編譯錯誤：Dog 值沒有 Speak
a = &Dog{}     // ✅ OK
```

> ⚠️ 這是 Go 新手最常踩的雷之一。**統一用 pointer receiver 就少 80% 麻煩**。

## 3.7 ⭐ 組合取代繼承（Composition over Inheritance）

Go 沒有 class、沒有 extends、沒有 implements。
要表達「類別關係」，用兩個工具：

### 工具一：Struct Embedding（結構嵌入）

```go
type Animal struct {
    Name string
}
func (a Animal) Info() string { return "I am " + a.Name }
func (a Animal) Speak() string { return "(sound)" }

type Dog struct {
    Animal       // 嵌入：欄位 + 方法都「提升」(promoted) 到 Dog
    Breed string
}

// Dog 可以直接用 Animal 的方法
d := Dog{Animal: Animal{Name: "Rex"}, Breed: "Husky"}
d.Name        // "Rex"（提升的欄位）
d.Info()      // "I am Rex"（提升的方法）

// 覆寫（override）：自己定義同名方法
func (d Dog) Speak() string { return "Woof!" }
d.Speak()         // "Woof!"
d.Animal.Speak()  // "(sound)" —— 仍可顯式呼叫被遮蔽的方法（類似 super）
```

⚠️ **嵌入是「has-a」（組合），不是「is-a」（繼承）**。
```go
var a Animal = d  // ❌ 編譯錯誤：Dog 不是 Animal 子類
var a Animal = d.Animal  // ✅ 拆出嵌入欄位才能賦值
```

### 工具二：Interface（隱式滿足）

```go
type Speaker interface {
    Speak() string
}

func Greet(s Speaker) { fmt.Println(s.Speak()) }

Greet(d)  // ✅ Dog 隱式滿足 Speaker（不需要 implements）
```

## 3.8 OOP ↔ Go 對照表（必背）

| OOP 概念 | Go 對應 | 說明 |
|---|---|---|
| class | `struct` | 純資料容器 |
| field | struct field | |
| method | `func (r T) M()` | 綁定型別的函式 |
| extends | struct embedding | has-a，非繼承 |
| implements | 隱式滿足 interface | 不寫 implements |
| override | 定義同名 method 在外層 | 覆蓋提升的方法 |
| `super.method()` | `obj.EmbeddedType.Method()` | 顯式呼叫被遮蔽的 |
| abstract class | interface | Go 沒有 abstract |
| constructor | `func NewXxx() *Xxx` | 慣例函式 |
| static method | package level function | 沒 receiver 即可 |
| 多型（polymorphism） | interface | 不靠繼承 |
| 封裝（encapsulation） | 大寫 / 小寫名稱 | 大寫 export、小寫 package 私有 |
| friend / package private | 同 package 可見 | |
| `final class` | 沒有對應 | 用組合 + 不 export 達成 |
| destructor | `defer` / 手動 `Close()` | GC 處理記憶體；資源要顯式關 |

### 關鍵心態切換
- **不要問「該繼承誰」**，問「我需要哪些行為（interface）？」
- **不要設計巨大的 base class**，設計小而精準的 interface（`io.Reader` 只有一個方法）。
- **不要追求「is-a」**，多用 has-a 組合。

## 3.9 嵌入的進階陷阱

### 陷阱 1：嵌入指標未初始化

```go
type Server struct {
    *Logger        // 嵌入指標
    Addr string
}

s := Server{Addr: ":8080"}
s.Log("start")    // ❌ panic：Logger 是 nil
```

**解法**：
```go
s := Server{Logger: &Logger{}, Addr: ":8080"}
```

### 陷阱 2：兩個嵌入有同名方法

```go
type A struct{}; func (A) Hello() {}
type B struct{}; func (B) Hello() {}
type C struct{ A; B }

var c C
c.Hello()  // ❌ 編譯錯誤：ambiguous selector c.Hello
```

**解法**：在 C 上定義 Hello 覆蓋之，或顯式呼叫 `c.A.Hello()`。

### 陷阱 3：嵌入 interface
這個其實是**特性**而非陷阱：

```go
type ReadWriter interface {
    io.Reader   // interface 嵌入 interface
    io.Writer
}
```

也可以用在 struct，做「部分實作 + 委派」：
```go
type LoggingReader struct {
    io.Reader  // 任何 Reader 都能塞進來
}
func (l LoggingReader) Read(p []byte) (int, error) {
    log.Println("read")
    return l.Reader.Read(p)
}
```

## 3.10 Idiom 與 Anti-pattern

### ✅ Idiom
- struct literal 一律用具名欄位：`User{ID: 1, Name: "x"}`
- 統一 pointer receiver
- constructor 命名為 `NewXxx`、`NewXxxFromYY`
- 小 interface（1-3 method）寫在使用端
- 用 embedding 表達能力的擁有

### ❌ Anti-pattern
- `User{1, "x", 30}` 沒寫欄位名，欄位調順序就掛
- 一個 struct 同時混用 value receiver 與 pointer receiver
- 把 Java 繼承直翻成多層 embedding
- 巨大 interface（>5 method 就要懷疑）
- export 內部實作 struct 的所有欄位（破壞封裝）

---

## 重點回顧

- Slice 是「ptr + len + cap」三件組；append 可能新建底層 array。
- Map 不是 thread-safe；零值 map 不能寫。
- Struct 用具名欄位；method 統一 pointer receiver；method set 決定 interface 滿足。
- **組合取代繼承**：embedding 表達 has-a；interface 表達行為。
- 心態：問「需要什麼行為」而不是「要繼承誰」。

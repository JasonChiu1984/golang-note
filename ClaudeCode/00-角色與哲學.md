# 第 0 章 角色設定與 Go 設計哲學

> 「Go is about composing simple things into complex programs.」— Rob Pike

本章不講語法；目的是讓你**用 Go 工程師的視角**閱讀後續章節。

---

## 0.1 Go 是為什麼而生的（Why Go）

Go 由 Robert Griesemer、Rob Pike、Ken Thompson 於 2007 年在 Google 啟動，2009 年公開。當時 Google 內部苦於：

- C++ 編譯極慢、語法龐大；新人上手要好幾個月。
- Java 啟動慢、記憶體佔用高、生態複雜。
- Python 動態型別、效能不足以撐起伺服器叢集。

Go 的設計目標是：**靜態型別 + 編譯後單一執行檔 + 編譯快 + 內建併發 + 簡單到「整個語言能塞進一張紙」**。

| 比較項 | C++ | Java | Python | **Go** |
|---|---|---|---|---|
| 編譯時間 | 慢 | 中 | n/a | **極快** |
| 部署 | 動態連結地獄 | JVM | 直譯器 | **單一靜態執行檔** |
| 併發 | 執行緒 + 鎖 | 執行緒 + 鎖 | GIL 限制 | **goroutine + channel** |
| 學習曲線（語法） | 陡峭 | 中等 | 平緩 | **平緩（25 個關鍵字）** |
| 泛型 | template（複雜） | 有 | 動態 | **1.18+ 加入，刻意保守** |

## 0.2 設計哲學的五個關鍵詞

### (1) Simplicity（簡單）
Go 全語言只有 **25 個關鍵字**：

```
break        default      func         interface    select
case         defer        go           map          struct
chan         else         goto         package      switch
const        fallthrough  if           range        type
continue     for          import       return       var
```

對照 C++ 有 90+ 個、Java 有 50+ 個。少即是多——能在腦中完整裝下整個語言，就是 Go 的核心競爭力。

### (2) Readability（可讀性）
- 一個 package 只有**一種正確寫法**：`gofmt` 強制格式統一。
- 變數名短，但有意義（`i`、`r`、`buf` 是慣例；`UserAccountController` 反而不 Go-like）。
- 「If in doubt, leave it out.」——不確定要不要加，那就不要加。

### (3) Composition over Inheritance（組合取代繼承）
- 沒有 `class`、沒有 `extends`、沒有 `implements`。
- 用 **`struct` + 嵌入（embedding）** 表達「擁有」關係。
- 用 **`interface`（隱式滿足）** 表達「行為」關係。

```go
// 不是 Animal extends LivingThing
// 而是 Animal 內嵌一份 LivingThing 的能力
type Animal struct {
    LivingThing  // embedding
    Species string
}
```

### (4) Errors are Values（錯誤是值）
- 沒有 `try / catch / finally`。
- 函式回傳 `(value, error)`，呼叫者**每一行都要決定**怎麼處理。
- 這看起來很囉唆，但讓錯誤路徑成為「程式設計的一等公民」。

```go
data, err := os.ReadFile("config.yaml")
if err != nil {
    return fmt.Errorf("讀取設定檔失敗: %w", err)
}
```

> **`panic` 不是 exception**。它代表「程式碼有 bug」（programmer error），如：陣列越界、nil pointer dereference。Library 不應 `panic`。

### (5) Concurrency is built-in（併發是內建的）
- `go funcCall()` 一個關鍵字就啟動 goroutine（2-8 KB stack，可開十萬個）。
- channel 是「會說話的 pipe」：`ch <- x` 送、`<-ch` 收。
- 名言：**「Don't communicate by sharing memory; share memory by communicating.」**

## 0.3 Go 工程師的視角（Mindset）

擁有 20 年 Go 經驗的工程師，會以以下原則判斷程式碼品質：

| 原則 | 解讀 |
|---|---|
| Make the zero value useful | `var b bytes.Buffer` 即可使用，不用 New |
| A little copying is better than a little dependency | 寧可多寫幾行，不要為了 DRY 引入巨大依賴 |
| Clear is better than clever | 讀者花 30 秒看懂 ≫ 你少打 5 行字 |
| Errors are part of your API | 錯誤訊息不是 debug log，是給呼叫端看的契約 |
| The bigger the interface, the weaker the abstraction | 1-2 method 的 interface > 20 method 的 interface |
| Don't panic | library 不 panic，遇到錯誤回傳 error |
| Channels orchestrate; mutexes serialize | 編排流程用 channel；保護單一狀態用 mutex |

## 0.4 與其他語言常見的「文化衝突」

從其他語言來的工程師，最常踩的觀念落差：

### 來自 Java / C# 的人
- **沒有 class** → 用 `struct` + `method`。
- **沒有 constructor** → 慣例寫一個 `func NewXxx() *Xxx`。
- **沒有 generics 的時代很長** → 1.18 才有，所以標準庫設計傾向 `interface{}`（現為 `any`）；現代寫法應優先 generics。
- **沒有 try-catch** → 每個錯誤都要顯式處理；`defer` 取代 `finally`。

### 來自 Python / JavaScript 的人
- **強型別 + 編譯期檢查**：`int + string` 直接編譯錯誤。
- **沒有 list comprehension**：用 for 迴圈即可。
- **沒有真正的 OOP**：別硬把繼承翻譯成 embedding；Go 的 interface 才是抽象主力。

### 來自 C / C++ 的人
- **有 GC**（garbage collector，垃圾收集器）：不要 `free`，但要注意 goroutine leak。
- **指標但無指標運算**：可以 `&v` 取址、`*p` 解參考，但不能 `p++`。
- **沒有巨集（macro）、沒有運算子重載（operator overloading）**。

## 0.5 本書的 AI 輔助使用方式

如果你用 AI 工具（如 Claude）幫忙寫 Go：

1. **明確指定版本**：「Go 1.22，請使用 generics 與 `slices` 套件」。
2. **明確指定風格**：「請用 pointer receiver、錯誤包裝用 `%w`、不要 panic」。
3. **要求 idiomatic**：「請用 Go 慣用寫法，不要把 Java/Python 的習慣帶進來」。
4. **要求測試**：「請附 table-driven test 與 benchmark」。

## 重點回顧（Recap）

- Go = 靜態型別 + 編譯快 + 單一執行檔 + 內建併發。
- 25 個關鍵字、一種格式、一條正路。
- 組合取代繼承、介面隱式滿足、錯誤是值、併發內建。
- 別把 Java/Python 習慣硬翻過來；要學會「Go-like」的思考。

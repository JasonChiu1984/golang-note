# 附錄 B 常見陷阱速查（Common Pitfalls）

> Go 工程師血淚換來的 15 個陷阱。寫之前掃一眼、debug 時翻一翻。

---

## B.1 nil interface ≠ typed nil

### 症狀
```go
func bad() error {
    var e *MyError  // typed nil
    return e        // ⚠️ 回傳的 error 不是 nil！
}

err := bad()
if err != nil {     // 進來了
    fmt.Println("oops")
}
```

### 原因
interface 是 `(type, value)` 兩格資訊。
`return e` 時 type=`*MyError`、value=nil → interface 不是 nil。

### 解法
要 nil 就明確 `return nil`：

```go
func ok() error {
    if /* nothing wrong */ {
        return nil
    }
    return &MyError{}
}
```

## B.2 slice append 共享底層 array

### 症狀
```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3]      // [2 3]，與 a 共用
b = append(b, 99)
fmt.Println(a)   // [1 2 3 99 5]  —— a 被改了！
```

### 原因
`b` 的 cap 來自 a，append 還沒滿 → 直接寫入。

### 解法
- 要獨立副本：`slices.Clone(a[1:3])` 或 `append([]int{}, a[1:3]...)`
- 用 `s = a[i:j:j]`（限制 cap）防止後續 append 落到 a 上：
  ```go
  b := a[1:3:3]  // len=2, cap=2，append 必新建
  ```

## B.3 goroutine leak

### 症狀
```go
func bad() {
    ch := make(chan int)
    go func() {
        v := <-ch  // 永遠不會收到，goroutine 永遠卡住
    }()
    // 函式 return，但 goroutine 還在
}
```

### 解法：每個 goroutine 都要有 ctx.Done() 退出路徑

```go
func ok(ctx context.Context) {
    ch := make(chan int)
    go func() {
        select {
        case v := <-ch: handle(v)
        case <-ctx.Done(): return
        }
    }()
}
```

偵測：`go.uber.org/goleak`。

## B.4 map 併發寫 → fatal

### 症狀
```go
var m = map[string]int{}

go func() { m["a"] = 1 }()
go func() { m["b"] = 2 }()
// fatal error: concurrent map writes
```

⚠️ 是 **fatal error**，不是 panic，**recover 救不了**。

### 解法
```go
var (
    mu sync.Mutex
    m  = map[string]int{}
)
mu.Lock(); m["a"] = 1; mu.Unlock()
```

或 `sync.Map`（讀多寫少且 key 動態）。

## B.5 range 取的是副本

### 症狀
```go
type User struct{ Name string }
users := []User{{Name: "a"}, {Name: "b"}}

for _, u := range users {
    u.Name = "x"  // 改的是副本，原 slice 不變
}
fmt.Println(users)  // [{a} {b}]
```

### 解法
- 用 index：`users[i].Name = "x"`
- 改成 pointer slice：`[]*User`

## B.6 for + defer 累積

### 症狀
```go
for _, p := range paths {
    f, _ := os.Open(p)
    defer f.Close()  // ❌ 全部到外層函式才關
    // process f
}
```

### 解法
包成內層函式：
```go
for _, p := range paths {
    func() {
        f, _ := os.Open(p)
        defer f.Close()
        // process
    }()
}
```

## B.7 字串 len 不是字元數

### 症狀
```go
s := "你好"
len(s)   // 6（每個中文字 3 bytes，UTF-8）
```

### 解法
```go
import "unicode/utf8"
utf8.RuneCountInString(s)  // 2

// 或轉 []rune
r := []rune(s)
len(r)  // 2
r[0]    // '你'
```

## B.8 shadow 變數（特別是 err）

### 症狀
```go
data, err := fetch()
if err != nil { return err }

if data != nil {
    data, err := process(data)  // ⚠️ 用了 :=，這裡的 err 是新的
    if err != nil { return err }
    use(data)
}
// 外面的 err 沒被改
```

### 解法
- 用 `=` 不用 `:=` 重複賦值
- 開啟 `golangci-lint` 的 `shadow` 檢查

## B.9 嵌入指標未初始化

### 症狀
```go
type Server struct {
    *Logger
    Addr string
}
s := Server{Addr: ":8080"}
s.Log("start")  // panic: nil pointer
```

### 解法
建構時記得初始化：
```go
s := Server{Logger: &Logger{}, Addr: ":8080"}
```

## B.10 method set 不匹配 interface

### 症狀
```go
type Animal interface { Speak() }
type Dog struct{}
func (d *Dog) Speak() {}   // pointer receiver

var a Animal
a = Dog{}      // ❌ Dog 值的 method set 不含 Speak
a = &Dog{}     // ✅ OK
```

### 解法
- 統一用 pointer receiver
- 或用 `&Dog{}` 賦值給 interface

## B.11 close channel 兩次 / send 後 close

```go
ch := make(chan int)
close(ch)
close(ch)        // panic: close of closed channel

ch2 := make(chan int)
close(ch2)
ch2 <- 1         // panic: send on closed channel
```

### 解法
**只有 sender 該 close**；多 sender 用 `sync.Once`：
```go
var once sync.Once
once.Do(func() { close(ch) })
```

## B.12 對 nil channel 操作（永遠阻塞）

```go
var ch chan int
ch <- 1    // 永遠阻塞
<-ch       // 永遠阻塞
```

### 用法（其實是特性）
在 select 中可以**動態關閉某 case**：
```go
var ch <-chan int
if !ready { ch = nil }  // 這個 case 就不會被選中

select {
case v := <-ch: ...
case <-ctx.Done(): ...
}
```

## B.13 init() 順序不可依賴

### 症狀
同 package 多個 `init()`：執行順序由檔名字母序決定，但依賴它就脆。
跨 package：被 import 的 package init 先跑，但**不要依賴**。

### 解法
寧可寫 `func New() *X` 由 main 顯式呼叫；保留 `init` 給「真的非寫不可」的場合。

## B.14 time.Time 的零值不是 1970-01-01

```go
var t time.Time
fmt.Println(t)  // 0001-01-01 00:00:00 +0000 UTC（不是 epoch！）
fmt.Println(t.IsZero())  // true
fmt.Println(t.Unix())    // -62135596800（負數）
```

### 解法
- 判斷「未設定」用 `t.IsZero()`，**不要用 `t == time.Time{}`**
- 序列化前先檢查
- DB 裡可選欄位用 `*time.Time` 或 `sql.NullTime`

## B.15 fmt.Errorf 沒包就丟掉根因

### 症狀
```go
if err != nil {
    return fmt.Errorf("save failed: %v", err)  // ⚠️ %v 不是 wrap
}
// 之後 errors.Is(err, sql.ErrNoRows) 永遠 false
```

### 解法
用 `%w`：
```go
return fmt.Errorf("save failed: %w", err)
```

## B.16 結構欄位對齊浪費記憶體

### 症狀
```go
type Bad struct {
    a bool      // 1 byte，但對齊後實際 8
    b int64     // 8
    c bool      // 1，對齊後 8
}
// 總計：24 bytes
```

### 解法
按大小排序：
```go
type Good struct {
    b int64     // 8
    a bool      // 1
    c bool      // 1
    // 6 byte padding
}
// 總計：16 bytes
```

工具：`fieldalignment`（`go install golang.org/x/tools/go/analysis/passes/fieldalignment/cmd/fieldalignment@latest`）。

⚠️ **小型專案不要為了這個影響可讀性**——大量重複的 struct 才值得優化。

## 速查表（Quick Reference）

| 陷阱 | 解法（一句話） |
|---|---|
| nil interface ≠ typed nil | 回傳 `nil` 而非 typed nil pointer |
| append 共享底層 array | `slices.Clone` 或 `s[i:j:j]` |
| goroutine leak | 加 `<-ctx.Done()` 退出路徑 |
| map 併發寫 crash | `sync.Mutex` 或 `sync.Map` |
| range 是副本 | 用 index 或 `[]*T` |
| for 內 defer | 包成內層函式 |
| `len("中文") = 6` | `utf8.RuneCountInString` 或 `[]rune` |
| shadow err | 用 `=` 不用 `:=` |
| 嵌入指標未初始化 | 建構時 `&Logger{}` |
| method set 不匹配 | 統一 pointer receiver |
| double close channel | `sync.Once` |
| nil channel 永遠阻塞 | 反用：select 動態關 case |
| init 順序不可依賴 | 改用顯式 `New()` |
| `time.Time{}` ≠ epoch | `t.IsZero()` |
| `%v` 沒包錯誤 | 用 `%w` |
| struct 對齊 | 大欄位放前面 + `fieldalignment` |

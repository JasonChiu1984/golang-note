# 第 1 章 環境與專案結構

> 把工具裝對、把目錄擺對，後面寫 code 才不會跌跌撞撞。

## 1.1 支援平台與安裝（Install）

### 支援平台（Supported Platforms）
Go 是少數真正「一次寫好、各處編譯」的語言：

| OS | 架構（Architecture） |
|---|---|
| Linux | amd64、arm64、arm（Raspberry Pi）、386、mips、ppc64、s390x |
| macOS | arm64（Apple Silicon）、amd64（Intel） |
| Windows | amd64、386、arm64 |
| FreeBSD / OpenBSD / NetBSD | amd64、arm |
| WebAssembly | wasm |

### 三大平台安裝方式

```bash
# macOS
brew install go

# Linux (Debian/Ubuntu)
sudo apt install golang-go     # 注意：套件庫版本通常較舊
# 推薦改用官方 tarball
wget https://go.dev/dl/go1.22.0.linux-amd64.tar.gz
sudo tar -C /usr/local -xzf go1.22.0.linux-amd64.tar.gz
echo 'export PATH=$PATH:/usr/local/go/bin' >> ~/.bashrc

# Windows：到官網下載 .msi
# https://go.dev/dl/
```

### 驗證
```bash
go version
# go version go1.22.0 darwin/arm64

go env GOROOT GOPATH
# /opt/homebrew/Cellar/go/1.22.0/libexec
# /Users/you/go
```

## 1.2 重要環境變數（Environment Variables）

| 變數 | 預設 | 說明 |
|---|---|---|
| `GOROOT` | 安裝路徑 | Go 編譯器與標準庫位置；**通常不用自己設** |
| `GOPATH` | `~/go` | 第三方套件下載與工具安裝目錄 |
| `GOBIN` | `$GOPATH/bin` | `go install` 輸出位置；**記得加進 `PATH`** |
| `GOOS` | 當前 OS | 編譯目標作業系統（`linux` / `darwin` / `windows`） |
| `GOARCH` | 當前架構 | 編譯目標 CPU 架構（`amd64` / `arm64`） |
| `GOPROXY` | `https://proxy.golang.org,direct` | 模組代理；中國大陸常設 `https://goproxy.cn` |
| `GOPRIVATE` | 空 | 私有模組路徑模式，例：`*.corp.com,github.com/myorg/*` |
| `GOSUMDB` | `sum.golang.org` | 校驗資料庫；私有模組通常設 `off` |
| `GOFLAGS` | 空 | 預設 flag，例：`-mod=mod` |
| `CGO_ENABLED` | 1 | 是否啟用 cgo；交叉編譯靜態執行檔常設 `0` |

查看全部：`go env`

## 1.3 工具鏈（Toolchain）

Go 的工具鏈**內建在 `go` 命令裡**，不需要 `npm` / `pip` / `cargo` 這種額外工具。

| 指令 | 用途 |
|---|---|
| `go run .` | 編譯並立即執行（不留執行檔） |
| `go build` | 編譯，輸出當前目錄；`-o bin/app` 指定輸出位置 |
| `go install` | 編譯並安裝到 `$GOBIN` |
| `go test ./...` | 跑整個 module 的測試 |
| `go test -race -cover ./...` | 加 race detector 與覆蓋率 |
| `go test -bench=.` | 跑 benchmark |
| `go fmt ./...` | 格式化（**寫完就跑**） |
| `go vet ./...` | 靜態分析（找可疑程式碼） |
| `go mod init <module>` | 初始化 module |
| `go mod tidy` | 同步 `go.mod` 與實際 import |
| `go mod graph` | 顯示依賴樹 |
| `go doc <package>` | 顯示 package 文件 |
| `go tool pprof` | 效能分析（CPU / Memory） |
| `go generate ./...` | 跑 `//go:generate` 指令 |

### 第三方常用工具
```bash
# 自動裝在 $GOBIN
go install golang.org/x/tools/cmd/goimports@latest    # 自動整理 import
go install honnef.co/go/tools/cmd/staticcheck@latest  # 比 vet 更強的 linter
go install github.com/golangci/golangci-lint/cmd/golangci-lint@latest  # 集合多種 linter
go install github.com/cosmtrek/air@latest             # 熱重載開發
```

### IDE / Editor
- **VS Code + Go extension**（最主流，內建 LSP）
- **GoLand**（JetBrains，付費，重度使用者愛用）
- **Neovim + gopls**（手動派）

## 1.4 Hello World 完整流程（First Project）

```bash
mkdir hello && cd hello
go mod init github.com/you/hello
```

`main.go`：
```go
package main

import "fmt"

func main() {
    fmt.Println("Hello, Go 1.22!")
}
```

執行：
```bash
go run .
# Hello, Go 1.22!

go build -o bin/hello .
./bin/hello
```

`go.mod` 會自動產生：
```
module github.com/you/hello

go 1.22
```

> **重點**：module 名稱建議用「實際的 repo 路徑」（即使尚未推上去），這樣未來搬遷不用大改。

## 1.5 標準專案目錄慣例（Project Layout）

Go 官方**沒有強制**目錄結構，但社群有一份廣為遵循的 [`golang-standards/project-layout`](https://github.com/golang-standards/project-layout)。對於中大型專案：

```
my-service/
├── cmd/                     # 每個子目錄 = 一個可執行檔
│   ├── api/
│   │   └── main.go          # 越薄越好，只組裝依賴
│   └── worker/
│       └── main.go
├── internal/                # ⭐ Go 強制：只有本 module 能 import
│   ├── domain/              # 核心商業邏輯（entity、value object）
│   ├── repository/          # 持久化層
│   ├── service/             # 應用服務層
│   └── transport/           # HTTP / gRPC handler
├── pkg/                     # 可被外部 module import 的通用工具
│   └── httpx/               # ⚠️ 慎用；確認真的有對外開放需求才放
├── api/                     # API 規格
│   ├── openapi.yaml
│   └── proto/
├── configs/                 # 設定檔範本（不放真實機密）
│   └── config.example.yaml
├── deployments/
│   ├── Dockerfile
│   └── k8s/
├── scripts/                 # 開發、CI 用的 shell 腳本
├── test/                    # E2E 測試、testdata（單元測試與原始碼同層）
├── docs/                    # 設計文件
├── go.mod
├── go.sum
├── Makefile
└── README.md
```

### 三大關鍵目錄

#### `cmd/` — 入口
- 每個子目錄編成一支 binary。
- `main()` 只做：讀設定 → 建立依賴 → 啟動 server → 等待 shutdown。
- 不寫商業邏輯。

```go
// cmd/api/main.go
func main() {
    cfg := config.Load()
    db := mustOpenDB(cfg.DSN)
    svc := service.New(db)
    h := transport.NewHTTP(svc)
    log.Fatal(http.ListenAndServe(cfg.Addr, h))
}
```

#### `internal/` — 核心（強制隔離）
- Go 編譯器**強制檢查**：`internal/` 目錄下的 package 只能被它的「父 module」import。
- 範例：`github.com/you/svc/internal/domain` 只能被 `github.com/you/svc/...` 下的 package 用；其他人 import 會編譯錯誤。
- 用途：保護核心邏輯不被外部濫用。

#### `pkg/` — 對外公開
- 沒有編譯器強制，純粹是「告訴別人：這裡的東西可以放心 import」。
- **慎用**！絕大多數新手不需要 `pkg/`，把東西放 `internal/` 就好；確認真的需要對外輸出再說。

## 1.6 Module、Package、檔案的關係

```
module  ── github.com/you/svc          （= go.mod 所在目錄）
   └── package  ── service              （= 一個目錄）
         ├── service.go                  （同 package 同目錄）
         ├── service_test.go
         └── helper.go
```

**規則**：
1. 一個目錄 = 一個 package（檔名可任意，但 `package X` 宣告必須一致）。
2. 一個 module = 一個 `go.mod`（一份依賴清單）。
3. 子目錄是**獨立 package**，不是「子 package」（Go 沒有 nested package 的概念）。
4. 從 module 外部 import 用完整路徑：
   ```go
   import "github.com/you/svc/internal/service"
   ```

## 1.7 Idiom 與 Anti-pattern

### ✅ Idiom
- **`cmd/<name>/main.go` 只做組裝**，邏輯放 `internal/`。
- 用 **`Makefile`** 包裝 `go build`、`go test`、`docker build` 流程。
- 提交 `go.sum` 進版控（保證可重現 build）。
- IDE 設定**存檔自動 `goimports` + `gofmt`**。

### ❌ Anti-pattern
- 把所有檔案丟在 root：`main.go`、`user.go`、`db.go` 全擠在一起 → 沒有可維護性。
- `pkg/` 裝一堆只有自己用的程式 → 應該放 `internal/`。
- 自訂 `vendor/` 鎖版本 → 用 `go.sum` 就夠了；除非有特殊需求（離線 build）。
- `import "."` 或大量別名 → 讓人讀不懂從哪來的。

## 1.8 Makefile 範本

```makefile
APP := myapp
BIN := bin/$(APP)
GO_VERSION := 1.22

.PHONY: build test lint run docker clean

build:
	go build -o $(BIN) ./cmd/api

test:
	go test -race -cover ./...

lint:
	golangci-lint run

run:
	go run ./cmd/api

docker:
	docker build -t $(APP):latest .

clean:
	rm -rf bin/
```

## 重點回顧

- 安裝：`brew install go`，記得 `GOBIN` 加進 `PATH`。
- 工具鏈內建在 `go` 命令；常用 `run` / `build` / `test` / `mod tidy` / `fmt` / `vet`。
- 目錄三大主角：`cmd/`（薄入口）、`internal/`（核心強制隔離）、`pkg/`（對外，慎用）。
- 一個目錄 = 一個 package；一個 `go.mod` = 一個 module。
- 用 Makefile 包裝重複指令，CI/CD 才不會散落。

## 2. 修正前後差異

| 面向 | 修正前 | 修正後 |
|---|---|---|
| Deadlock retry | 固定 `time.Sleep`，backoff 期間不監聽 context | backoff 期間同時監聽 timer 與 `ctx.Done()` |
| Request cancellation | context 取消後仍可能進入下一次 retry | context 取消後立即回傳 `ctx.Err()` |
| Queue side effect | 取消路徑沒有專門測試保證不 enqueue | 測試固定取消後 queue 不收到 task |
| 教材說明 | transaction boundary 有提到 retry，但取消語意不足 | 第 7 / 11 章與速查表補上 cancellation gate |

## 3. 更新後學習重點

學生讀到本輪內容後，應能理解：

1. Retry 應同時設計成功路徑、失敗路徑與取消路徑。
2. `context.Context` 不只是 HTTP handler 的 timeout，也應傳到 service、repository 與 worker 邊界。
3. Production retry backoff 不應用無條件 `time.Sleep`。
4. 取消後不得繼續執行會產生副作用的動作，例如 DB transaction 或 queue enqueue。
5. 回歸測試應固定「取消後沒有發生什麼」，而不只固定回傳錯誤。

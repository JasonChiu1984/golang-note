## 4. Configuration

Prometheus config 需至少包含：

1. `scrape_interval: 15s`
2. `evaluation_interval: 15s`
3. `rule_files` 指向 `/etc/prometheus/rules/production-api-worker-alerts.yml`
4. `job_name: production-api-worker`
5. `metrics_path: /metrics`
6. target `api:8080`

OpenAPI spec 需至少包含：

1. `openapi: 3.1.0`
2. `POST /jobs`
3. `GET /jobs/{id}`
4. `GET /livez`
5. `GET /readyz`
6. `GET /metrics`
7. `bearerAuth`
8. `X-Request-ID`
9. `JobInput`、`Job`、`ErrorEnvelope`
10. `invalid_input`、`not_found`、`queue_full`、`request_timeout`、`unauthorized`、`internal_error`

## 7. Troubleshooting

| 可能問題 | 處理方式 |
|---|---|
| Prometheus targets down | 檢查 `docker compose ps`、API `/readyz`、`/metrics`、profile 是否啟用 |
| rules 未載入 | 檢查 `rule_files` path 與 Compose volume mount |
| `/metrics` 401 | 確認是否設定 `API_KEY`，正式環境改用 bearer token file / secret mount |
| OpenAPI 與 Go tests 漂移 | 先以 Go contract tests 為行為真相，再更新 OpenAPI 與 Markdown |
| Docker 不可用 | 靜態 checks 仍可通過，runtime monitoring profile 留待有 Docker 環境驗證 |

## 8. Best Practices

1. Prometheus config、alert rules、runbook 與 README 不分開維護。
2. API 合約要同時保留 Markdown、OpenAPI 與 Go contract tests。
3. 本地 Prometheus profile 保持無 secret；正式 scrape auth 由部署平台管理。
4. 每次重產 `docs/index.html` 後都跑 link fix 與 HTML home link check。

## 1. Overview

依據本輪審查，v1.0.39 已完成 HTTP server timeout contract。下一個需要更新的部分是把 `X-Request-ID` request correlation 從「已存在的測試與文件說明」提升為「獨立、可重跑、可由 CI 阻擋漂移的 contract gate」。

## 2. Architecture

| 更新項 | 需要修改 | 驗收標準 |
|---|---|---|
| Static gate | 新增 `scripts/check-request-correlation-contract.mjs` | 可檢查 README、OpenAPI、API contract、handler、tests、章節、Cheat Sheet、整合 HTML、CI 與 Makefile |
| CI workflow | `.github/workflows/ci.yml` 新增 request correlation check | GitHub Actions root-course job 會跑新 gate |
| Makefile | `production-api-worker/Makefile` 新增 `request-correlation-check` | 本機可用 make 重跑 |
| OpenAPI | `production-api-worker/api/openapi.yaml` 版本升級到 v1.0.40 | description 保留 `X-Request-ID` 與 `request.id` |
| 教材文件 | README、production README、API contract、第 7 / 11 章、Cheat Sheet、整合 HTML | 讀者能知道為何與如何驗收 request correlation |

## 3. Configuration

本輪不新增環境變數。`X-Request-ID` 是 HTTP request correlation 基礎能力，應保持預設啟用，不提供關閉開關。

## 4. Verification

git diff --check

## 5. Troubleshooting

| 問題 | 可能原因 | 處理方式 |
|---|---|---|
| static gate 找不到 `request.id` | OpenAPI 或文件未補 trace attribute 說明 | 補上 request correlation 文字 |
| Go test 失敗 | handler middleware 未保留 client supplied request id | 檢查 `requestContextMiddleware` |
| docs check 失敗 | `docs/index.html` 未由整合 HTML 同步 | 重跑 `node scripts/fix-docs-index-links.mjs --sync-source` |

## 6. Best Practices

- 新增 production contract 時，必須同時更新 Go tests、OpenAPI、README、章節、CI 與 release note。
- 不要只用文字宣稱可觀測性；需有可重跑 gate 固定 request id 入口。
- 若未來導入 API Gateway，需追加 gateway forwarding / overwrite policy。

## 7. Summary

本輪更新聚焦 `Request correlation contract gate`，不擴大改 runtime 行為，採最小風險方式補齊教程的 production observability 驗收層。

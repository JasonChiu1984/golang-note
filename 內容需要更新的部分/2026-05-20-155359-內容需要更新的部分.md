## 本輪更新主題

正式加入 HTTP server timeout contract，讓 `production-api-worker` 的 timeout 行為不再停留於 `main.go` 硬編碼，而是形成可設定、可測試、可文件化、可 CI 固定的 production 操作合約。

## 更新清單

| 類別 | 需更新內容 | 驗收方式 |
|---|---|---|
| Config | 新增 `HTTP_READ_HEADER_TIMEOUT`、`HTTP_READ_TIMEOUT`、`HTTP_WRITE_TIMEOUT`、`HTTP_IDLE_TIMEOUT`、`HTTP_SHUTDOWN_TIMEOUT`、`QUEUE_DRAIN_TIMEOUT` 預設與 env parsing | `go test ./internal/config -run TestLoadFromLookup -count=1` |
| API worker 啟動 | 將 timeout 套用到 `http.Server`，並讓 shutdown / queue drain timeout 來自 config | `go test ./cmd/api-worker -run TestHTTPServerTimeoutContract -count=1` |
| Static gate | 新增 `scripts/check-http-timeout-contract.mjs` 與 `make http-timeout-check` | `node scripts/check-http-timeout-contract.mjs` |
| CI | GitHub Actions root-course 與 production-contract 納入 HTTP timeout gate | YAML parse 與 script check |
| 文件 | README、production README、API contract、章節 7/11、Cheat Sheet、整合 HTML 課程標示 timeout contract | `rg` 與 docs index sync/check |
| 版本 | `VERSION`、`CHANGELOG.md` 更新至 `v1.0.39` | tag / commit message 對齊 |

## 不在本輪範圍

| 項目 | 原因 |
|---|---|
| API gateway / Ingress timeout 範本 | 需要指定部署平台，先不臆測 |
| 負載測試與 slow client 整合測試 | 需要較長 runtime 與 socket 測試環境，本輪先固定 config / main contract |
| Alertmanager 或正式 OTLP backend | 屬於後續 observability 平台整合，不影響本輪 timeout contract |

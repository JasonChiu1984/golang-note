## 1. Architecture

本次更新把 production diagnostics 從概念補成可測合約：

- `production-api-worker` 新增 `ENABLE_PPROF` 與 `PPROF_TOKEN`。
- pprof 預設不註冊 route，避免 `/debug/pprof/` 常態暴露。
- 啟用 pprof 時必須有 `PPROF_TOKEN` 或 `API_KEY`，否則設定載入 fail fast。
- API handler 只在合法 `Authorization: Bearer <token>` 時允許讀 pprof endpoint。

## 3. Configuration

| Env | 預設 | 行為 |
|---|---|---|
| `ENABLE_PPROF` | `false` | `true` 時註冊 `/debug/pprof/` |
| `PPROF_TOKEN` | 空字串 | 優先作為 pprof Bearer token |
| `API_KEY` | 空字串 | `PPROF_TOKEN` 空值時可作為 pprof token fallback |

Docker Compose 已加入 `ENABLE_PPROF` 與 `PPROF_TOKEN` passthrough，預設仍保持關閉。

## 5. Troubleshooting

| 症狀 | 處置 |
|---|---|
| `/debug/pprof/` 回 404 | 確認是否刻意保持 `ENABLE_PPROF=false` |
| `/debug/pprof/` 回 401 | 帶 `Authorization: Bearer <PPROF_TOKEN>` 或 fallback 的 `API_KEY` |
| `go tool pprof` 無法直接帶 token | 先用 `curl -H 'Authorization: Bearer ...'` 下載 `profile.pb.gz`，再執行 `go tool pprof profile.pb.gz` |

## 6. Risk Notes

- pprof profile 可能含 heap、goroutine、cmdline、trace 等敏感資訊，不應提交到 repo。
- `ENABLE_PPROF=true` 應只用於短期事故診斷，正式環境還需搭配 VPN、內網來源限制或 gateway policy。
- 本次未執行 `docker compose up` runtime smoke，因目前驗證目標是 diagnostics contract 與 Compose config；Docker daemon 狀態需在部署環境另行確認。

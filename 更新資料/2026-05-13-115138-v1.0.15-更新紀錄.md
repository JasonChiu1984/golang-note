## 1. 本次更新摘要

本輪以資深工程師角度重新審查 Go 教程的 production project 深度，確認目前已具備 API contract、observability correlation、readiness/draining、panic recovery 與 worker queue shutdown safety。最小但高價值的缺口是 service deadlock retry 的 cancellation 行為尚未可測化。

已將 `production-api-worker` 的 deadlock retry backoff 改為 context-aware，並把 retry cancellation 納入教程、速查表、康乃爾筆記、API 合約與 release gate。

## 3. 程式修改

| 項目 | 說明 |
|---|---|
| Context-aware backoff | `withDeadlockRetry` 在 deadlock 後用 timer 等待，但同時監聽 `ctx.Done()` |
| 取消後停止 | context canceled / deadline exceeded 時立即回傳 `ctx.Err()` |
| 最後一次 retry | 保留最多 3 次 retry 語意，不在最後一次 deadlock 後多等待 |
| Service 解耦 | `app.Service` 改依賴小型 `Store` / `Observability` interface，讓 app 層測試不需編譯 Postgres / OpenTelemetry 外部套件 |
| 測試保護 | `TestCreateJobStopsDeadlockRetryWhenContextCanceled` 確認取消後只呼叫一次 `WithTx`，且 queue 沒有收到 task |

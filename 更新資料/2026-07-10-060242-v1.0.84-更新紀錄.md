## GitHub push

前置收斂嘗試：

- 背景：上一輪 `v1.0.83` 的 remote release 已建立在 `origin/main=ce24a9a94a8304d391b59c09be3f43e64e52252a`，local `HEAD` / local `v1.0.83^{}` 保留 final release-record evidence。
- 指令：`git push --force-with-lease=main:ce24a9a94a8304d391b59c09be3f43e64e52252a origin main && git push --force origin refs/tags/v1.0.83`
- 結果：失敗，`Could not resolve host: github.com`。

本輪狀態：local release complete / remote push blocked。

- 本輪 release commit 已建立，並以 `Merge remote v1.0.83 release state before v1.0.84` merge commit 保留 `origin/main=ce24a9a94a8304d391b59c09be3f43e64e52252a` 的遠端歷史父節點。
- Annotated tag：`v1.0.84`
- 指令：`git push origin main refs/tags/v1.0.84`
- 結果：失敗，`Could not resolve host: github.com`。
- 最終本地狀態：
  - local `HEAD` / local `v1.0.84^{}` 將在本紀錄回填後重新對齊。
  - local `v1.0.83^{}` 仍保留 final release-record evidence commit。
  - `origin/main` 仍停在 remote v1.0.83 初次成功 push commit `ce24a9a94a8304d391b59c09be3f43e64e52252a`。
  - 本機 `main...origin/main` 為 ahead 3；因 merge commit 已納入 `origin/main`，DNS 恢復後可直接 fast-forward 推送 `main` 與 `v1.0.84` tag。

恢復方式：

```bash
git push origin main refs/tags/v1.0.84
git push --force-with-lease=main:ce24a9a94a8304d391b59c09be3f43e64e52252a origin main
git push --force origin refs/tags/v1.0.83
```

## 1. 修改摘要

本輪以資深工程師角度重新檢查 `production-api-worker` 的服務生命週期後，發現 queue shutdown path 存在 enqueue 與 close 競態風險。修正後，`Queue.Enqueue` 與 `Queue.ShutdownContext` 共用同步邊界，shutdown 後的新 enqueue 會回 `worker.ErrClosed`，不會送入已關閉 channel。

## 5. 受限環境備註

目前 sandbox 仍限制外部網路與部分全域 Go module cache 寫入，因此完整 `production-api-worker go test ./...` 被 Prometheus / OpenTelemetry / pgx 依賴下載擋住。本輪已透過 `Observer` interface 讓 `internal/worker` 可在 repo-local cache 下獨立通過測試，降低 queue lifecycle 測試對外部依賴的耦合。

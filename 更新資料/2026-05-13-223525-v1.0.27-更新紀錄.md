# v1.0.27 更新紀錄

- 日期時間：2026-05-13 22:35:25 +0800 CST

- 主題：GPU 效能比較、Assembly / 微服務教程拆分、Docs index 連結自動修正

## 修改摘要

1. `docs/c-python-go-performance-supplement.html` 補上 GPU / Metal 真實效能比較，將 CPU sequential workload、GPU kernel time、GPU total time 分開說明，避免錯誤倍率解讀。
2. 新增 `examples/performance-comparison/gpu/bench.swift`，並擴充 `TestCode/performance-comparison/run-real-benchmark.sh` 產生 CPU / GPU 綜合測試報告。
3. 將 Assembly 與微服務拆成兩個獨立教程頁：
   - `docs/golang-assembly-tutorial.html`
   - `docs/golang-microservice-tutorial.html`
4. `docs/golang-assembly-microservice.html` 改為過渡入口，保留舊 URL 並導向新教程。
5. 新增 `scripts/fix-docs-index-links.mjs`，每次重產 `docs/index.html` 後可自動修正 GitHub Pages `docs/` root 相對連結。
6. `docs/index.html` 修正補充頁、ReleaseNote、source code、benchmark 與 jump-card 的連結位置，避免 `/docs`、`/ReleaseNote` 404。

## 風險與注意事項

- GitHub Pages 專案根目錄為 `/golang-note/`，因此 `docs/index.html` 內部連結必須以 `docs/` root 為基準，不可使用會跳到帳號根目錄的 `/docs/...` 或 `../docs/...`。
- `scripts/fix-docs-index-links.mjs --sync-source` 會先用 `圖解筆記3-4整合/golang-complete-visual-course.html` 覆蓋 `docs/index.html`，再套用 Pages 路徑修正；後續重產主頁時需以此指令作為固定步驟。
- GPU 結果只適用於 data-parallel workload，不可直接與 sequential CPU loop 合併成單一通用倍率。
